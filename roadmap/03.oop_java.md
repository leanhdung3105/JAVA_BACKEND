> **Mục tiêu:** Nắm vững 4 tính chất OOP và ứng dụng vào thiết kế code Java.

## 1. Class và Object

> **🔍 WHAT:** Class là bản thiết kế (blueprint) định nghĩa thuộc tính và hành vi; Object là thực thể cụ thể được tạo ra từ class đó.
>
> **💡 WHY:** OOP giúp mô hình hóa thực thế thực tế thành code – User, Order, Product đều là các object. Giúp code có cấu trúc, dễ tái sử dụng và bảo trì.
>
> **⚙️ HOW:** Khai báo class với `class`, tạo object với `new`. Fields là dữ liệu, methods là hành vi. Constructor là method đặc biệt để khởi tạo object. `this` tham chiếu đến object hiện tại.
>
> **📍 WHEN/WHERE:** Mọi thứ trong Java đều là class – Entity (ánh xạ DB), DTO (truyền dữ liệu), Service (business logic), Controller (xử lý HTTP request) đều là các class trong dự án Spring Boot.

```java
public class Person {
    // Fields
    private String name;
    private int age;

    // Constructor
    public Person(String name, int age) {
        this.name = name;
        this.age = age;
    }

    // Getter & Setter
    public String getName() { return name; }
    public void setName(String name) { this.name = name; }
    public int getAge() { return age; }
    public void setAge(int age) { this.age = age; }

    // Method
    public void introduce() {
        System.out.println("Tôi là " + name + ", " + age + " tuổi.");
    }

    @Override
    public String toString() {
        return "Person{name='" + name + "', age=" + age + "}";
    }
}

// Tạo object
Person person = new Person("Alice", 25);
person.introduce(); // Tôi là Alice, 25 tuổi.
```

> **📝 Giải thích chi tiết code:**
> * `private String name;`: Thuộc tính (field/instance variable) lưu trữ tên của đối tượng `Person`. Phạm vi `private` giới hạn biến này chỉ được truy cập trực tiếp từ bên trong class `Person`.
> * `public Person(String name, int age)`: Đây là **Constructor** (phương thức khởi tạo). Constructor trùng tên với class, không có kiểu trả về. Nó được gọi tự động khi dùng từ khóa `new` để tạo mới một đối tượng.
> * `this.name = name;`: Từ khóa `this` đại diện cho đối tượng hiện tại đang hoạt động. Phép gán này dùng để phân biệt giữa thuộc tính của class (`this.name`) và tham số truyền vào phương thức (`name`).
> * `getName()` / `setName()`: Các phương thức **Getter** (lấy dữ liệu) và **Setter** (gán/sửa dữ liệu) công khai. Đây là cách chuẩn để giao tiếp với các thuộc tính bị ẩn giấu (`private`).
> * `@Override public String toString()`: Ghi đè phương thức mặc định `toString()` kế thừa từ lớp cha cao nhất là `Object`. Khi ta in đối tượng ra console (`System.out.println(person)`), Java sẽ tự động gọi phương thức `toString()` này để hiển thị thông tin rõ ràng thay vì in ra mã băm (hashcode).
> * `new Person("Alice", 25)`: Dùng toán tử `new` để cấp phát bộ nhớ trên vùng nhớ Heap cho một đối tượng `Person` cụ thể, đồng thời gọi Constructor để truyền các giá trị khởi tạo.

## 2. Tính đóng gói (Encapsulation)

> **🔍 WHAT:** Encapsulation là tính chất che giấu dữ liệu bên trong class, chỉ cho phép truy cập thông qua các phương thức được kiểm soát (getter/setter).
>
> **💡 WHY:** Ngăn không cho code bên ngoài trực tiếp thay đổi trạng thái object theo cách không hợp lệ (ví dụ: đặt số dư tài khoản âm). Bảo vệ tính toàn vẹn dữ liệu.
>
> **⚙️ HOW:** Khai báo fields là `private`, cung cấp `public` getter/setter với logic validation nếu cần. Dùng Lombok `@Data`, `@Getter`, `@Setter` để tự động sinh getter/setter.
>
> **📍 WHEN/WHERE:** Áp dụng cho mọi class có fields – Entity, DTO, Service. Đặc biệt quan trọng trong Entity để kiểm soát trạng thái của domain object.

```java
public class BankAccount {
    private double balance;  // private – che giấu bên trong

    public BankAccount(double initialBalance) {
        if (initialBalance < 0) throw new IllegalArgumentException("Số dư không được âm");
        this.balance = initialBalance;
    }

    public double getBalance() {
        return balance;  // chỉ đọc
    }

    public void deposit(double amount) {
        if (amount <= 0) throw new IllegalArgumentException("Số tiền phải > 0");
        balance += amount;
    }

    public void withdraw(double amount) {
        if (amount > balance) throw new IllegalArgumentException("Không đủ số dư");
        balance -= amount;
    }
}

BankAccount account = new BankAccount(1000);
account.deposit(500);
account.withdraw(200);
System.out.println(account.getBalance()); // 1300.0
// account.balance = -1000; // ❌ Compile error
```

> **📝 Giải thích chi tiết code:**
> * `private double balance`: Biến lưu trữ số dư tài khoản được cài đặt ở chế độ `private`. Code bên ngoài class không thể can thiệp sửa trực tiếp như `account.balance = -1000`.
> * `if (initialBalance < 0) ...`: Validation chặn đứng mọi hành vi tạo tài khoản có số dư âm ngay từ lúc khởi tạo đối tượng bằng cách ném ra ngoại lệ.
> * `getBalance()`: Chỉ cung cấp Getter để đọc giá trị mà không cung cấp Setter (`setBalance()`). Muốn thay đổi trạng thái của `balance`, code bắt buộc phải thông qua hai nghiệp vụ có kiểm soát là nạp tiền (`deposit`) hoặc rút tiền (`withdraw`).
> * `deposit` / `withdraw`: Các phương thức nghiệp vụ kiểm soát việc thay đổi dữ liệu, thực hiện kiểm tra điều kiện (validation) trước khi thay đổi giá trị của `balance`, đảm bảo số tiền gửi/rút hợp lệ và tài khoản không bị rút âm tiền.

## 3. Tính kế thừa (Inheritance)

> **🔍 WHAT:** Inheritance cho phép class con (subclass) kế thừa các thuộc tính và phương thức từ class cha (superclass), đồng thời mở rộng hoặc ghi đè hành vi.
>
> **💡 WHY:** Tái sử dụng code, tránh lặp lại – nếu nhiều loại tài khoản (Savings, Checking) có chung thuộc tính (balance, owner), kế thừa từ Account chung giúp giảm code trùng.
>
> **⚙️ HOW:** Dùng từ khóa `extends`. `super()` gọi constructor cha, `super.method()` gọi method cha. `@Override` đánh dấu method ghi đè. Java chỉ cho phép đơn kế thừa (1 class cha), dùng interface để "kế thừa" nhiều.
>
> **📍 WHEN/WHERE:** Trong Spring Boot: `BaseEntity` (chứa createdAt, updatedAt) được kế thừa bởi mọi Entity; Exception hierarchy (`BusinessException extends RuntimeException`); Abstract service classes.

```java
// Lớp cha
public class Animal {
    protected String name;

    public Animal(String name) { this.name = name; }

    public void eat() { System.out.println(name + " đang ăn"); }
    public void sleep() { System.out.println(name + " đang ngủ"); }
}

// Lớp con
public class Dog extends Animal {
    private String breed;

    public Dog(String name, String breed) {
        super(name);  // gọi constructor cha
        this.breed = breed;
    }

    public void bark() { System.out.println(name + " đang sủa!"); }

    @Override
    public void eat() {
        System.out.println(name + " đang ăn xương");
    }
}

Dog dog = new Dog("Buddy", "Labrador");
dog.eat();   // Buddy đang ăn xương (override)
dog.sleep(); // Buddy đang ngủ (kế thừa)
dog.bark();  // Buddy đang sủa!
```

> **📝 Giải thích chi tiết code:**
> * `protected String name`: Modifier `protected` cho phép lớp con `Dog` có quyền truy cập trực tiếp biến `name` của lớp cha `Animal`, trong khi các lớp ngoài package vẫn không thể can thiệp.
> * `public class Dog extends Animal`: Từ khóa `extends` chỉ định lớp `Dog` kế thừa lớp `Animal`. `Animal` là lớp cha (Superclass) và `Dog` là lớp con (Subclass).
> * `super(name)`: Hàm gọi Constructor của lớp cha `Animal`. Lệnh này **bắt buộc phải nằm ở dòng đầu tiên** trong Constructor của lớp con.
> * `dog.sleep()`: Biến `dog` kiểu lớp con gọi được phương thức `sleep()` mặc dù trong class `Dog` không hề viết phương thức này – đó là nhờ kế thừa từ lớp cha `Animal`.
> * `@Override public void eat()`: Tính chất **Method Overriding** (Ghi đè phương thức). Lớp con định nghĩa lại hành vi phương thức `eat()` của lớp cha. Khi gọi `dog.eat()`, chương trình sẽ ưu tiên chạy phiên bản cụ thể ở lớp con.

## 4. Tính đa hình (Polymorphism)

> **🔍 WHAT:** Polymorphism là khả năng một đối tượng có thể biểu hiện theo nhiều dạng khác nhau. Method cùng tên nhưng hành vi khác nhau tùy vào kiểu object thực tế.
>
> **💡 WHY:** Cho phép viết code generic, xử lý nhiều loại object khác nhau qua cùng một interface – ví dụ: duyệt danh sách Shape và tính area mà không cần biết là Circle hay Rectangle.
>
> **⚙️ HOW:** Runtime polymorphism: ghi đè method ở subclass, khi gọi qua biến kiểu cha sẽ chạy method của class con thực tế (dynamic dispatch). Compile-time polymorphism: overloading (cùng tên, khác tham số).
>
> **📍 WHEN/WHERE:** Design pattern Strategy sử dụng polymorphism để thay đổi thuật toán; Spring IoC container inject đúng implementation vào interface dựa vào polymorphism.

```java
// Đa hình runtime
public abstract class Shape {
    public abstract double area();

    public void printArea() {
        System.out.println("Diện tích: " + area()); // gọi đúng method của subclass
    }
}

public class Circle extends Shape {
    private double radius;
    public Circle(double radius) { this.radius = radius; }
    @Override
    public double area() { return Math.PI * radius * radius; }
}

public class Rectangle extends Shape {
    private double width, height;
    public Rectangle(double w, double h) { this.width = w; this.height = h; }
    @Override
    public double area() { return width * height; }
}

// Xử lý đa hình
List<Shape> shapes = List.of(new Circle(5), new Rectangle(4, 6), new Circle(3));
for (Shape shape : shapes) {
    shape.printArea(); // gọi đúng method của từng class con
}

// Đa hình compile-time (overloading)
public class Calculator {
    public int add(int a, int b) { return a + b; }
    public double add(double a, double b) { return a + b; }
    public int add(int a, int b, int c) { return a + b + c; }
}
```

> **📝 Giải thích chi tiết code:**
> * `public abstract class Shape`: Class cha trừu tượng chứa phương thức trừu tượng `public abstract double area()`. Phương thức trừu tượng không có phần thân code thực thi, bắt buộc các lớp con kế thừa nó phải tự định nghĩa logic tính toán cụ thể.
> * `List<Shape> shapes`: Tạo một List chứa các đối tượng có kiểu khai báo là lớp cha `Shape`. Trong List này có thể chứa cả instance của `Circle` và `Rectangle` nhờ tính chất đa hình (đối tượng lớp con có thể gán cho biến tham chiếu lớp cha).
> * `shape.printArea()`: Khi vòng lặp chạy qua từng phần tử `shape`, câu lệnh `shape.printArea()` sẽ gọi `area()`. Nhờ cơ chế **Dynamic Binding** (Liên kết động tại thời điểm chạy), Java tự động nhận diện `shape` đó là đối tượng thật nào để thực hiện đúng logic `area()` tương ứng của `Circle` hay `Rectangle`.
> * `Calculator`: Minh họa đa hình lúc biên dịch (Compile-time Polymorphism) thông qua **Method Overloading**. Trình biên dịch tự phân tích tham số truyền vào hàm để map chính xác với signature hàm phù hợp.

## 5. Tính trừu tượng (Abstraction)

> **🔍 WHAT:** Abstraction là tính chất che giấu chi tiết cài đặt phức tạp, chỉ phơi bày những gì cần thiết ra bên ngoài. Thực hiện qua Abstract Class và Interface.
>
> **💡 WHY:** Giúp define "hợp đồng" (contract) giữa các module – code phụ thuộc vào interface thay vì implementation cụ thể, dễ thay thế và test (mock). Đây là nền tảng của DI và SOLID.
>
> **⚙️ HOW:** **Abstract class**: có thể có cả method abstract lẫn concrete, có state (fields), đơn kế thừa. **Interface**: chỉ định contract (abstract methods), Java 8+ thêm `default` methods, đa implement được.
>
> **📍 WHEN/WHERE:** Interface dùng cho tất cả Service layer trong Spring Boot (`UserService` interface + `UserServiceImpl`); Repository interfaces (Spring Data JPA); Strategy pattern. Abstract class dùng cho `BaseEntity`, `BaseController`.

```java
// Abstract Class
public abstract class Vehicle {
    protected String brand;

    public Vehicle(String brand) { this.brand = brand; }

    public abstract void startEngine(); // bắt buộc subclass implement

    public void displayInfo() { // method chung
        System.out.println("Thương hiệu: " + brand);
    }
}

// Interface
public interface Flyable {
    void fly();
    default void land() { System.out.println("Đang hạ cánh..."); }
}

public interface Swimmable {
    void swim();
}

// Implement nhiều interface (không thể extends nhiều class)
public class Duck extends Animal implements Flyable, Swimmable {
    public Duck(String name) { super(name); }

    @Override public void fly() { System.out.println(name + " bay"); }
    @Override public void swim() { System.out.println(name + " bơi"); }
}
```

> **📝 Giải thích chi tiết code:**
> * `public abstract void startEngine()`: Một phương thức trừu tượng trong lớp trừu tượng `Vehicle`. Lớp trừu tượng cho phép lưu trữ thuộc tính chung (`brand`) và phương thức có sẵn logic (`displayInfo`), đồng thời ép các lớp con phải triển khai logic riêng cho các phương thức trừu tượng (`startEngine`).
> * `public interface Flyable`: Khai báo một Interface. Interface chỉ định nghĩa "giao kèo/hành vi" mà không chứa trạng thái (không có instance fields). Tất cả phương thức mặc định đều là `public abstract`.
> * `default void land()`: Từ Java 8, Interface có thêm phương thức **default** chứa sẵn phần thân code. Lớp implement nó không bắt buộc phải override phương thức này mà có thể kế thừa và dùng lại trực tiếp.
> * `class Duck extends Animal implements Flyable, Swimmable`: Java chỉ hỗ trợ **Đơn kế thừa** lớp (`extends Animal`), nhưng hỗ trợ **Đa triển khai** nhiều Interface (`implements Flyable, Swimmable`). Điều này cho phép một lớp đại diện cho nhiều kiểu hành vi khác nhau một cách linh hoạt.

## 6. Static & Final

> **🔍 WHAT:** `static` là thành phần thuộc về class chứ không phải object (dùng chung). `final` là thành phần không thể thay đổi sau khi khởi tạo (constant, immutable class).
>
> **💡 WHY:** `static` dùng cho utility methods và constants không cần instance. `final` đảm bảo tính bất biến – quan trọng với constants, immutable value objects và thread safety.
>
> **⚙️ HOW:** `static field/method` truy cập qua tên class. `final field` phải gán trong constructor. `final class` không thể kế thừa. `final method` không thể override.
>
> **📍 WHEN/WHERE:** `static final` cho constants (`MAX_RETRY = 3`). Static utility methods trong Helper/Utils classes. `final` trong constructor injection để đảm bảo dependency không null và immutable.

```java
public class MathUtils {
    public static final double PI = 3.14159265358979; // constant

    public static int square(int n) { // không cần tạo object
        return n * n;
    }
}

MathUtils.PI;
MathUtils.square(5); // 25

// final class – không kế thừa được
public final class ImmutablePoint {
    private final int x; // phải gán trong constructor
    private final int y;

    public ImmutablePoint(int x, int y) {
        this.x = x;
        this.y = y;
    }
    // x, y không thể thay đổi sau khi tạo
}
```

> **📝 Giải thích chi tiết code:**
> * `public static final double PI`: Sự kết hợp hoàn hảo để tạo nên một **Hằng số (Constant)** trong Java:
>   * `static`: Giá trị thuộc về class `MathUtils`, được nạp một lần duy nhất vào bộ nhớ và dùng chung cho mọi nơi mà không cần tạo đối tượng.
>   * `final`: Đảm bảo giá trị của biến này là bất biến, không thể bị gán lại sau khi đã khai báo.
> * `public static int square(...)`: Phương thức tĩnh, được dùng để thực hiện các xử lý mang tính thuần túy logic đầu vào/đầu ra, không phụ thuộc vào trạng thái riêng của bất kỳ đối tượng nào. Có thể gọi trực tiếp thông qua tên class: `MathUtils.square(5)`.
> * `public final class ImmutablePoint`: Đánh dấu class là `final` giúp ngăn cản hoàn toàn việc các class khác kế thừa (extend) nó nhằm thay đổi hành vi hay chèn mã độc.
> * `private final int x`: Thuộc tính được khai báo là `final` bắt buộc phải gán giá trị một lần duy nhất (hoặc ngay lúc khai báo, hoặc trong Constructor). Sau khi gán, giá trị này không thể thay đổi, đảm bảo tính **Immutable** của đối tượng.

## 7. Enum

> **🔍 WHAT:** Enum (Enumeration) là kiểu dữ liệu đặc biệt đại diện cho một tập hợp hằng số có tên, có thể mang thêm dữ liệu và phương thức.
>
> **💡 WHY:** Thay vì dùng String hay int để biểu diễn trạng thái (dễ typo và không type-safe), Enum ràng buộc chỉ các giá trị hợp lệ được phép – code rõ ràng, an toàn và dễ switch-case.
>
> **⚙️ HOW:** Khai báo với `enum`, các giá trị được liệt kê. Enum có thể có constructor, fields và methods. JPA lưu enum bằng `@Enumerated(EnumType.STRING)` để lưu tên thay vì index số.
>
> **📍 WHEN/WHERE:** Dùng cho trạng thái đơn hàng (`PENDING`, `SHIPPED`, `DELIVERED`), role người dùng (`USER`, `ADMIN`), loại thanh toán, bất kỳ tập giá trị cố định nào trong domain.

```java
public enum OrderStatus {
    PENDING("Chờ xử lý"),
    PROCESSING("Đang xử lý"),
    SHIPPED("Đã giao"),
    DELIVERED("Đã nhận"),
    CANCELLED("Đã hủy");

    private final String description;

    OrderStatus(String description) { this.description = description; }

    public String getDescription() { return description; }
}

// Sử dụng
OrderStatus status = OrderStatus.PENDING;
System.out.println(status.getDescription()); // Chờ xử lý

switch (status) {
    case PENDING -> System.out.println("Đang chờ xử lý đơn hàng");
    case DELIVERED -> System.out.println("Đơn hàng đã giao thành công");
    default -> System.out.println("Trạng thái: " + status.getDescription());
}
```

> **📝 Giải thích chi tiết code:**
> * `public enum OrderStatus`: Khai báo một kiểu dữ liệu liệt kê `OrderStatus`. Mỗi giá trị được liệt kê (`PENDING`, `PROCESSING`...) thực chất là một đối tượng hằng số tĩnh của chính lớp enum này.
> * `private final String description`: Thuộc tính mang thêm thông tin cho hằng số. Enum có thể có các thuộc tính và phương thức giống như một class bình thường.
> * `OrderStatus(String description)`: Constructor của Enum. Điểm đặc biệt là constructor này **luôn luôn mang phạm vi private ngầm định** (không thể viết `public OrderStatus(...)`), ngăn không cho code bên ngoài tự ý tạo mới các giá trị hằng số khác ngoài các giá trị đã được liệt kê trước.
> * `case PENDING -> ...`: Switch Expression sử dụng rất mượt mà với kiểu dữ liệu Enum. Trình biên dịch có thể kiểm tra xem bạn đã xử lý hết tất cả các trường hợp của Enum hay chưa để đưa ra cảnh báo an toàn.

## 8. Record (Java 16+)

> **🔍 WHAT:** Record là kiểu class đặc biệt trong Java 16+ dành cho immutable data carrier – tự động sinh constructor, getter, `equals()`, `hashCode()`, `toString()`.
>
> **💡 WHY:** Giảm đáng kể boilerplate code cho các class chỉ chứa dữ liệu (DTO, value objects). Thay vì 50 dòng code với Lombok, Record chỉ cần 1 dòng.
>
> **⚙️ HOW:** `record TênRecord(TypeField1 field1, TypeField2 field2) {}`. Getter là tên field (không có "get" prefix). Compact constructor dùng để validate đầu vào. Record là final, không thể kế thừa.
>
> **📍 WHEN/WHERE:** Lý tưởng cho DTO (Data Transfer Object) trong Spring Boot – `CreateUserRequest`, `UserResponse`, `LoginRequest`. Tốt hơn POJO thông thường khi dữ liệu không cần thay đổi sau khi tạo.

```java
// Record – 1 dòng thay cho ~30 dòng POJO
public record Point(int x, int y) {}

public record UserDTO(String name, String email, int age) {
    // Compact constructor để validate
    public UserDTO {
        if (age < 0) throw new IllegalArgumentException("Tuổi phải >= 0");
        name = name.trim();
        email = email.toLowerCase();
    }
}

Point p = new Point(3, 4);
System.out.println(p.x());  // 3 (getter không có "get")
System.out.println(p.y());  // 4
System.out.println(p);      // Point[x=3, y=4]

UserDTO user = new UserDTO("Alice", "Alice@Example.com", 25);
System.out.println(user.email()); // "alice@example.com" (đã lowercase)
```

> **📝 Giải thích chi tiết code:**
> * `public record Point(int x, int y) {}`: Khai báo một Record. Trình biên dịch sẽ tự sinh ra:
>   * Các thuộc tính `private final int x;` và `private final int y;`.
>   * Constructor chuẩn nhận vào các đối số: `public Point(int x, int y)`.
>   * Các phương thức Getter: `p.x()` và `p.y()` (lưu ý không có tiền tố "get").
>   * Các phương thức tự động sinh: `toString()`, `equals()`, `hashCode()`.
> * `public UserDTO { ... }`: Đây là một **Compact Constructor** (Hàm khởi tạo rút gọn). Nó không có tham số truyền vào ở phần khai báo signature. Java dùng phương thức này để can thiệp thực hiện validation và tiền xử lý dữ liệu (chuẩn hóa dữ liệu như `trim()` hay `toLowerCase()`) trước khi gán dữ liệu cho các thuộc tính thực tế.
> * `Record` luôn là một lớp `final` và bất biến (các thuộc tính luôn là `final`), không thể thừa kế lớp khác và không thể bị lớp khác kế thừa.

## 9. Design Principles cơ bản

> **🔍 WHAT:** Design Principles là các nguyên tắc hướng dẫn thiết kế code để dễ bảo trì, mở rộng và test. SOLID là bộ 5 nguyên tắc quan trọng nhất.
>
> **💡 WHY:** Code không tuân theo nguyên tắc thiết kế trở nên khó thay đổi (brittle), khó test, khó đọc – dẫn đến technical debt. SOLID giúp code flexible và dễ mở rộng tính năng mới.
>
> **⚙️ HOW:** Áp dụng từng nguyên tắc: S – mỗi class 1 trách nhiệm; O – thêm tính năng mới bằng cách mở rộng, không sửa code cũ; L – subclass phải thay thế được superclass; I – interface nhỏ cụ thể; D – phụ thuộc vào abstraction.
>
> **📍 WHEN/WHERE:** Áp dụng khi thiết kế architecture của dự án – phân chia layer (Controller/Service/Repository), tạo interface cho Service, dùng DI container của Spring. Đây là nền tảng để Spring Framework hoạt động.

| Nguyên tắc | Ý nghĩa |
|-----------|---------|
| **S** – Single Responsibility | Một class chỉ làm một việc |
| **O** – Open/Closed | Mở để mở rộng, đóng để sửa đổi |
| **L** – Liskov Substitution | Lớp con có thể thay thế lớp cha |
| **I** – Interface Segregation | Nhiều interface nhỏ hơn một interface lớn |
| **D** – Dependency Inversion | Phụ thuộc vào abstraction, không vào implementation |

```java
// DIP Example – phụ thuộc interface thay vì class cụ thể
public interface EmailService {
    void sendEmail(String to, String content);
}

public class GmailService implements EmailService {
    @Override
    public void sendEmail(String to, String content) { /* ... */ }
}

public class OrderService {
    private final EmailService emailService; // phụ thuộc interface

    public OrderService(EmailService emailService) { // inject từ ngoài vào
        this.emailService = emailService;
    }

    public void placeOrder() {
        emailService.sendEmail("user@example.com", "Đơn hàng đã đặt!");
        // Có thể swap GmailService → SendGridService mà không sửa OrderService
    }
}
```

> **📝 Giải thích chi tiết code:**
> * `public interface EmailService`: Tạo một Abstraction (Interface) đại diện cho khả năng gửi Email. Đây là điểm mấu chốt để đảo ngược sự phụ thuộc.
> * `private final EmailService emailService;`: Lớp `OrderService` khai báo thuộc tính phụ thuộc dựa trên kiểu Interface `EmailService` chứ không phụ thuộc trực tiếp vào một lớp triển khai cụ thể nào như `GmailService`.
> * `public OrderService(EmailService emailService)`: Cung cấp Constructor để tiêm dependency (Dependency Injection) từ môi trường bên ngoài vào. Việc này giúp `OrderService` hoàn toàn độc lập, tách rời logic gửi mail thực tế. Khi cần đổi sang sử dụng nhà cung cấp email khác, ta chỉ cần viết lớp implement mới (ví dụ `SendGridService implements EmailService`) và tiêm vào mà hoàn toàn **không cần sửa một dòng code nào** trong lớp `OrderService` (Tuân thủ nguyên lý đóng/mở Open/Closed).
