# 11. Docker & Deployment

> **Mục tiêu:** Đóng gói ứng dụng bằng Docker, triển khai lên server và quản lý môi trường với Docker Compose.

---

## 1. Docker Cơ bản

> **🔍 WHAT:** Docker là nền tảng containerization – đóng gói ứng dụng cùng với mọi dependencies vào một "container" có thể chạy nhất quán trên bất kỳ máy nào có Docker installed.
>
> **💡 WHY:** Giải quyết vấn đề "chạy được trên máy tôi nhưng không chạy được trên server". Container cô lập môi trường, đảm bảo dev/staging/production identical. Cũng dùng để run service phụ (DB, Redis) mà không cài trực tiếp.
>
> **⚙️ HOW:** `Dockerfile` định nghĩa cách build `Image`. Chạy `docker build` tạo Image, `docker run` tạo và chạy Container từ Image. `docker-compose` orchestrate nhiều container cùng lúc.
>
> **📍 WHEN/WHERE:** Phát triển: chạy PostgreSQL/Redis qua Docker thay vì cài local. Deployment: đóng gói Spring Boot app thành Docker image. CI/CD: build và push image lên registry (Docker Hub, ECR, GCR).

```bash
# Image management
docker pull postgres:15
docker images
docker rmi my-image

# Container
docker run -d -p 5432:5432 --name my-postgres \
  -e POSTGRES_PASSWORD=root postgres:15
docker ps              # đang chạy
docker logs my-postgres -f
docker exec -it my-postgres psql -U postgres

# Build image từ Dockerfile
docker build -t my-app:1.0 .
docker run -p 8080:8080 my-app:1.0
```

> **📝 Giải thích chi tiết các lệnh Docker CLI:**
> * `docker pull postgres:15`: Tải ảnh đóng gói (Image) Postgres phiên bản 15 từ kho lưu trữ đám mây Docker Hub về máy cục bộ.
> * `docker images`: Liệt kê danh sách toàn bộ các Docker Image hiện đang có sẵn trên máy của bạn.
> * `docker rmi my-image`: Xóa (Remove Image) một image không dùng đến khỏi máy để giải phóng dung lượng ổ đĩa.
> * `docker run -d -p 5432:5432 --name my-postgres -e POSTGRES_PASSWORD=root postgres:15`:
>   * `run`: Tạo và khởi chạy một container mới.
>   * `-d` (detached mode): Chạy ngầm container dưới background.
>   * `-p 5432:5432` (port forwarding): Ánh xạ cổng `5432` của máy thật (bên trái) vào cổng `5432` của container (bên phải).
>   * `--name my-postgres`: Đặt tên cho container để quản lý.
>   * `-e POSTGRES_PASSWORD=root`: Thiết lập biến môi trường (Environment Variable) để đặt mật khẩu root cho database là `root`.
> * `docker ps`: Liệt kê toàn bộ các container hiện đang ở trạng thái hoạt động (chạy). Thêm cờ `-a` để xem cả các container đã dừng (stopped).
> * `docker logs my-postgres -f`: Xem nhật ký hoạt động (logs) của container. Cờ `-f` (follow) giúp giữ kết nối Terminal để liên tục cập nhật log mới theo thời gian thực (giống `tail -f`).
> * `docker exec -it my-postgres psql -U postgres`:
>   * `exec`: Thực thi một câu lệnh trực tiếp bên trong container đang chạy.
>   * `-it` (interactive tty): Mở giao diện dòng lệnh tương tác trực tiếp với container.
>   * `psql -U postgres`: Chạy chương trình psql kết nối database bằng user `postgres` ngay trong môi trường container.
> * `docker build -t my-app:1.0 .`: Build một image mới dựa trên các chỉ thị trong file `Dockerfile`. Cờ `-t` để đặt tên và phiên bản (tag) cho image. Dấu chấm `.` chỉ định ngữ cảnh build ở chính thư mục hiện tại.

## 2. Viết Dockerfile cho Spring Boot

> **🔍 WHAT:** Dockerfile là file text chứa tập lệnh theo từng layer để build Docker Image cho ứng dụng Spring Boot – từ base JDK image, copy JAR, cấu hình đến lệnh khởi động.
>
> **💡 WHY:** Multi-stage build giúp image nhỏ hơn đáng kể (chỉ chứa JRE runtime, không có Maven/build tools). Image nhỏ hơn = upload nhanh hơn, pull nhanh hơn, bảo mật hơn (attack surface nhỏ hơn).
>
> **⚙️ HOW:** Stage 1 (build): dùng Maven image để compile và package JAR. Stage 2 (runtime): dùng JRE image nhỏ hơn, copy JAR từ stage 1. Layer caching: COPY pom.xml + download dependencies trước khi COPY source để tận dụng cache khi chỉ thay đổi code.
>
> **📍 WHEN/WHERE:** Mỗi dự án Spring Boot có 1 Dockerfile ở root. Build trong CI pipeline sau khi tests pass. Luôn dùng non-root user và chỉ định JAVA_OPTS để tuning JVM trong container.

```dockerfile
# Stage 1: Build
FROM maven:3.9-eclipse-temurin-17 AS build
WORKDIR /app
# Copy pom.xml trước để cache dependencies
COPY pom.xml .
RUN mvn dependency:go-offline -B
# Copy source và build
COPY src ./src
RUN mvn package -DskipTests

# Stage 2: Runtime (image nhỏ hơn nhiều)
FROM eclipse-temurin:17-jre-jammy
WORKDIR /app

# Non-root user – bảo mật
RUN groupadd -r spring && useradd -r -g spring spring
USER spring:spring

COPY --from=build /app/target/*.jar app.jar

# JVM tuning cho container environment
ENV JAVA_OPTS="-XX:+UseContainerSupport -XX:MaxRAMPercentage=75.0"

EXPOSE 8080
ENTRYPOINT ["sh", "-c", "java $JAVA_OPTS -jar app.jar"]
```

```bash
docker build -t my-spring-app:1.0 .
docker run -d --name my-app -p 8080:8080 \
  -e SPRING_PROFILES_ACTIVE=prod \
  -e DB_USERNAME=myuser \
  -e DB_PASSWORD=secret \
  my-spring-app:1.0
```

> **📝 Giải thích chi tiết mã Dockerfile (Multi-stage Build):**
> * **Multi-stage Build**: Kỹ thuật phân tách quá trình build thành nhiều giai đoạn (Stage). Stage 1 (`AS build`) sử dụng ảnh JDK đầy đủ và nặng nề chứa Maven để biên dịch code. Stage 2 chỉ sử dụng ảnh JRE nhẹ (chỉ chứa môi trường chạy, không chứa compiler) để chạy file `.jar` đã biên dịch xong. Kết quả là dung lượng file image cuối cùng giảm từ ~800MB xuống chỉ còn ~200MB.
> * `WORKDIR /app`: Đặt thư mục làm việc mặc định trong container là `/app`.
> * `RUN mvn dependency:go-offline -B`:
>   * Cú pháp `COPY pom.xml .` kết hợp với lệnh tải thư viện này giúp **tối ưu hóa Layer Caching** của Docker. Docker sẽ tự động cache lại layer tải thư viện này. Ở các lần build tiếp theo, nếu bạn chỉ sửa file code Java (`/src`) mà không thay đổi `pom.xml`, Docker sẽ bỏ qua việc tải lại thư viện, giúp thời gian build từ 5 phút giảm xuống chỉ còn 10 giây.
> * `RUN groupadd -r spring && useradd -r -g spring spring`:
>   * **Best Practice Bảo mật**: Tạo một tài khoản người dùng hạn chế (`spring`) để chạy ứng dụng trong container. Mặc định Docker chạy container dưới quyền quản trị tối cao (`root`). Nếu ứng dụng của bạn bị hacker tấn công qua lỗ hổng, hacker có thể chiếm quyền root của toàn bộ server vật lý. Chạy dưới quyền non-root ngăn ngừa hoàn toàn nguy cơ này.
> * `COPY --from=build ...`: Copy file jar đã build thành công từ Stage 1 (`build`) sang Stage 2.
> * `ENV JAVA_OPTS="-XX:+UseContainerSupport -XX:MaxRAMPercentage=75.0"`:
>   * `-XX:+UseContainerSupport`: Ép JVM tự nhận diện giới hạn tài nguyên RAM/CPU do Docker cấp phát (tránh lỗi JVM đọc nhầm RAM của máy chủ vật lý dẫn tới lỗi bị kernel kill vì tràn RAM - OOM Killed).
>   * `-XX:MaxRAMPercentage=75.0`: Chỉ định JVM được phép sử dụng tối đa 75% lượng RAM được cấp phát cho container.
> * `ENTRYPOINT`: Lệnh mặc định sẽ được thực thi khi container khởi chạy, thực hiện chạy ứng dụng Spring Boot kèm theo các cấu hình tối ưu JVM.

## 3. Docker Compose

> **🔍 WHAT:** Docker Compose là tool để định nghĩa và chạy multi-container applications – cấu hình tất cả services (app, DB, Redis, Nginx) trong file `docker-compose.yml` và khởi động bằng 1 lệnh.
>
> **💡 WHY:** Quản lý từng container riêng lẻ bằng lệnh `docker run` dài dòng và error-prone. Compose giúp: khai báo dependency giữa services (`depends_on`), share network tự động, quản lý volumes, dùng environment file.
>
> **⚙️ HOW:** Viết `docker-compose.yml` định nghĩa services, networks, volumes. `docker-compose up -d` khởi động tất cả. Services giao tiếp qua service name (thay vì localhost). `healthcheck` đảm bảo service sẵn sàng trước khi dependent service start.
>
> **📍 WHEN/WHERE:** Development environment: chạy toàn bộ stack (App + DB + Redis) với 1 lệnh. Production: deploy lên VPS dùng Compose (đơn giản hơn Kubernetes). CI: spin up dependencies để chạy integration test.

```yaml
version: '3.8'

services:
  postgres:
    image: postgres:15-alpine
    container_name: myapp-postgres
    restart: unless-stopped
    environment:
      POSTGRES_DB: mydb
      POSTGRES_USER: myuser
      POSTGRES_PASSWORD: ${DB_PASSWORD:-secret}
    volumes:
      - postgres_data:/var/lib/postgresql/data
    ports:
      - "5432:5432"
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U myuser -d mydb"]
      interval: 10s
      timeout: 5s
      retries: 5

  redis:
    image: redis:7-alpine
    container_name: myapp-redis
    restart: unless-stopped
    ports:
      - "6379:6379"
    volumes:
      - redis_data:/data

  app:
    build: .
    container_name: myapp
    restart: unless-stopped
    depends_on:
      postgres:
        condition: service_healthy  # chờ DB ready
    environment:
      SPRING_PROFILES_ACTIVE: prod
      SPRING_DATASOURCE_URL: jdbc:postgresql://postgres:5432/mydb  # service name
      SPRING_DATASOURCE_USERNAME: myuser
      SPRING_DATASOURCE_PASSWORD: ${DB_PASSWORD:-secret}
      JWT_SECRET: ${JWT_SECRET}
    ports:
      - "8080:8080"

volumes:
  postgres_data:
  redis_data:
```

```bash
docker-compose up -d          # khởi động
docker-compose logs -f app    # xem logs
docker-compose down           # dừng
docker-compose up -d --build app  # rebuild sau thay đổi code
```

> **📝 Giải thích chi tiết cấu hình Docker Compose:**
> * `restart: unless-stopped`: Cơ chế tự phục hồi. Nếu container bị crash hoặc khi hệ điều hành VPS tự khởi động lại, Docker Compose sẽ tự động khởi chạy lại container này một cách tự động.
> * `healthcheck`: Bộ tự kiểm tra sức khỏe dịch vụ. Nó chạy lệnh `pg_isready` mỗi 10 giây để xác nhận Postgres thật sự đã sẵn sàng chấp nhận các kết nối mạng.
> * `depends_on ... condition: service_healthy`: Ràng buộc thứ tự khởi động thông minh. Spring Boot App chỉ bắt đầu khởi chạy **khi và chỉ khi Postgres đã hoàn thành khởi động và ở trạng thái khỏe mạnh (`healthy`)**. Giúp ngăn ngừa lỗi sập ứng dụng lúc khởi động vì App kết nối tới DB quá sớm khi DB chưa load xong.
> * `postgres:5432`: Một tính năng tuyệt vời của Docker Compose. Docker tự động tạo một mạng ảo nội bộ (Internal Network) và thiết lập DNS nội bộ. Các container có thể gọi kết nối tới nhau trực tiếp thông qua **tên Service** (ở đây kết nối tới DB là `postgres`) thay vì dùng địa chỉ IP.
> * `${DB_PASSWORD:-secret}`: Đọc mật khẩu động từ file `.env` ngoài thư mục gốc. Nếu không tìm thấy biến `DB_PASSWORD`, hệ thống sẽ sử dụng giá trị mặc định là `"secret"`.
> * `docker-compose up -d --build app`: Lệnh rebuild lại riêng image của service `app` sau khi bạn có sự thay đổi mã nguồn Java và khởi động lại nó ngầm mà không làm ảnh hưởng tới các container DB và Redis đang chạy.

## 4. Nginx Configuration

> **🔍 WHAT:** Nginx là web server/reverse proxy – đứng trước Spring Boot app để xử lý SSL termination, load balancing, static file serving, rate limiting và gzip compression.
>
> **💡 WHY:** Spring Boot không nên expose trực tiếp ra internet. Nginx cung cấp: HTTPS/SSL, bảo vệ app bằng rate limiting, serve static files hiệu quả hơn Java, ẩn implementation details (port, server technology).
>
> **⚙️ HOW:** Cấu hình `upstream` trỏ vào Spring Boot container. `location /api/` proxy tất cả API request. Set `proxy_set_header` để truyền client IP thật. Cấu hình SSL certificate (Let's Encrypt miễn phí).
>
> **📍 WHEN/WHERE:** Bắt buộc trong production deployment. Trong development, gọi thẳng Spring Boot port. Luôn enable HTTPS cho production – dùng Let's Encrypt + Certbot để có SSL certificate miễn phí.

```nginx
http {
    upstream spring_app {
        server app:8080;  # service name trong docker-compose
    }

    # Redirect HTTP → HTTPS
    server {
        listen 80;
        server_name myapp.com;
        return 301 https://$host$request_uri;
    }

    server {
        listen 443 ssl http2;
        server_name myapp.com;

        ssl_certificate /etc/nginx/certs/fullchain.pem;
        ssl_certificate_key /etc/nginx/certs/privkey.pem;

        # Security headers
        add_header X-Frame-Options "SAMEORIGIN";
        add_header X-Content-Type-Options "nosniff";

        location /api/ {
            proxy_pass http://spring_app;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;
            proxy_connect_timeout 30s;
            proxy_read_timeout 60s;
        }
    }
}
```

> **📝 Giải thích chi tiết cấu hình Nginx:**
> * `upstream spring_app`: Định nghĩa nhóm máy chủ backend. Ở đây trỏ trực tiếp tới dịch vụ `app` cổng `8080` định nghĩa trong file compose.
> * `return 301 https://...`: Ràng buộc bảo mật. Tự động chuyển hướng (Redirect) toàn bộ các request sử dụng HTTP (cổng 80) không an toàn sang dạng HTTPS bảo mật (cổng 443).
> * `listen 443 ssl http2`: Lắng nghe kết nối bảo mật sử dụng giao thức **HTTP/2** thế hệ mới để tăng tối đa tốc độ tải trang nhờ tính chất ghép kênh dữ liệu (Multiplexing).
> * `ssl_certificate` / `ssl_certificate_key`: Cấu hình đường dẫn tới cặp chứng chỉ bảo mật SSL/TLS được cấp phát.
> * `proxy_pass http://spring_app`: Định tuyến và chuyển tiếp toàn bộ các request gửi tới đường dẫn `/api/` về cho cụm dịch vụ Spring Boot xử lý.
> * `proxy_set_header X-Real-IP $remote_addr`:
>   * **Cực kỳ quan trọng**: Vì đứng sau proxy Nginx, Spring Boot App sẽ luôn thấy IP gửi request là IP nội bộ của Nginx. Dòng cấu hình này đính kèm địa chỉ IP vật lý thực tế của người dùng ngoài internet vào Header của request để Spring Boot có thể đọc được chính xác địa chỉ IP của Client nhằm mục đích ghi log hoặc phân tích.

## 5. Triển khai lên VPS (Ubuntu)

> **🔍 WHAT:** VPS (Virtual Private Server) là server ảo trên cloud (DigitalOcean, Vultr, Linode...) mà bạn có toàn quyền kiểm soát – cài Docker, deploy app, cấu hình firewall.
>
> **💡 WHY:** Học cách deploy lên real server là kỹ năng quan trọng. VPS rẻ hơn managed services (Heroku, Railway), cho phép học full deployment stack thực tế. Giá từ $5-10/tháng phù hợp để học và làm portfolio.
>
> **⚙️ HOW:** SSH vào server, cài Docker, copy code (git clone hoặc scp), tạo `.env` file với secrets, chạy `docker-compose up -d`. Cài SSL với Certbot. Setup firewall (UFW) chỉ mở port 22, 80, 443.
>
> **📍 WHEN/WHERE:** Sau khi app hoạt động tốt trên local, deploy lên VPS để test với môi trường thực. Portfolio project nên deploy để hiring manager có thể test live. Production app nên có monitoring và backup.

```bash
# 1. Cài Docker trên Ubuntu nhanh bằng Script
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER

# 2. Clone project và cấu hình
git clone https://github.com/myorg/myapp.git
cd myapp
nano .env  # tạo file với các secrets nhạy cảm

# 3. Chạy ứng dụng
docker-compose up -d

# 4. Cài SSL tự động với Let's Encrypt + Certbot
sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d myapp.com -d www.myapp.com

# 5. Thiết lập tường lửa bảo mật (UFW - Uncomplicated Firewall)
sudo ufw allow 22/tcp   # SSH - kết nối VPS từ xa
sudo ufw allow 80/tcp   # HTTP
sudo ufw allow 443/tcp  # HTTPS
sudo ufw enable
```

> **📝 Giải thích chi tiết các lệnh triển khai:**
> * `usermod -aG docker $USER`: Thêm tài khoản người dùng hiện tại vào nhóm quản trị `docker` để bạn có thể thực thi các lệnh docker mà không cần gõ tiền tố `sudo` phiền phức trước mỗi lệnh.
> * `certbot --nginx`: Certbot sẽ tự động quét file cấu hình Nginx của bạn, tự thực hiện các bước xác thực tên miền với tổ chức Let's Encrypt phát hành chứng chỉ, tải về cặp file chứng chỉ SSL miễn phí và **tự cấu hình chèn mã cấu hình SSL vào file Nginx** của bạn một cách tự động chỉ trong vòng 1 phút.
> * `ufw allow 22/tcp`: Rất quan trọng! Bạn bắt buộc phải mở cổng SSH `22` trước khi kích hoạt tường lửa (`ufw enable`). Nếu quên dòng này, bạn sẽ lập tức bị đá ra khỏi VPS và vĩnh viễn không thể kết nối SSH lại vào server được nữa trừ khi cài lại hệ điều hành!
> * Các cổng khác (như `5432` của Postgres hay `8080` của App) sẽ bị tường lửa UFW **ngăn chặn hoàn toàn việc kết nối trực tiếp từ ngoài internet** để đảm bảo an toàn, bảo mật tuyệt đối cho hạ tầng database của bạn.

## 6. Health Check & Monitoring cơ bản

> **🔍 WHAT:** Health Check là endpoint `/actuator/health` báo cáo trạng thái ứng dụng (UP/DOWN) và các component phụ thuộc (DB, Redis). Monitoring là thu thập và hiển thị metrics theo thời gian thực.
>
> **💡 WHY:** Biết ngay khi ứng dụng gặp vấn đề thay vì chờ user báo lỗi. Load balancer dùng health check để không route traffic vào instance đang lỗi. Monitoring metrics giúp phát hiện performance degradation trước khi thành vấn đề nghiêm trọng.
>
> **⚙️ HOW:** Spring Actuator cung cấp sẵn `/actuator/health`. Docker health check tích hợp trong `docker-compose.yml`. Dùng `docker stats` xem resource usage. Setup alert khi CPU/memory vượt ngưỡng.
>
> **📍 WHEN/WHERE:** Bắt buộc trong production. Load balancer (AWS ALB, Nginx) dùng health endpoint. Kubernetes dùng làm liveness/readiness probe. Setup Uptime Robot (free) để alert khi site down.

```bash
# Kiểm tra health
curl https://myapp.com/actuator/health

# Resource monitoring
docker stats                    # real-time CPU/memory usage
docker-compose logs -f app | grep ERROR  # filter error logs
```

> **📝 Giải thích chi tiết lệnh:**
> * `docker stats`: Hiển thị bảng điều khiển động hiển thị thời gian thực lượng tài nguyên phần cứng (CPU %, bộ nhớ RAM đã dùng, băng thông mạng) của từng container đang tiêu thụ, giúp dev phát hiện nhanh lỗi rò rỉ bộ nhớ (Memory Leak).
> * `grep ERROR`: Lọc nhanh các dòng nhật ký hoạt động có chứa từ khóa lỗi `ERROR` để phục vụ công tác gỡ lỗi (debug) nhanh chóng trên server.
