# 🛠️ Thiết lập Môi trường Phát triển Java Backend

Hướng dẫn từng bước để cài đặt các công cụ cần thiết cho lập trình Java Backend.

---

## 1. Cài đặt Java (JDK)

> **🔍 WHAT:** JDK (Java Development Kit) là bộ công cụ phát triển Java, bao gồm trình biên dịch (`javac`), máy ảo Java (JVM) và các thư viện chuẩn.
>
> **💡 WHY:** Đây là nền tảng bắt buộc để chạy và biên dịch bất kỳ chương trình Java nào – không có JDK thì không thể lập trình Java.
>
> **⚙️ HOW:** Tải JDK từ trang chính thức (Oracle hoặc OpenJDK), cài đặt và cấu hình biến môi trường `JAVA_HOME` và `PATH` để hệ thống nhận diện được lệnh `java` và `javac`.
>
> **📍 WHEN/WHERE:** Cài ngay ở bước đầu tiên trên máy phát triển (local machine) trước khi làm bất cứ điều gì khác liên quan đến Java.

### Các bước cài đặt

1. Truy cập [https://adoptium.net/](https://adoptium.net/) hoặc [https://www.oracle.com/java/technologies/downloads/](https://www.oracle.com/java/technologies/downloads/)
2. Tải **JDK 17** (LTS) hoặc **JDK 21** (LTS mới nhất)
3. Cài đặt theo hướng dẫn của installer
4. Kiểm tra cài đặt:

```bash
java -version
javac -version
```

> **📝 Giải thích chi tiết lệnh:**
> * `java -version`: Kiểm tra phiên bản Máy ảo Java (JVM - Java Virtual Machine) hiện tại trên hệ thống. Lệnh này xác nhận môi trường chạy (Runtime) đã sẵn sàng.
> * `javac -version`: Kiểm tra phiên bản của Trình biên dịch Java (Java Compiler). Trình biên dịch có nhiệm vụ biên dịch mã nguồn `.java` thành mã bytecode `.class`. Có lệnh này chứng tỏ bạn đã cài đặt đúng JDK (Development Kit) chứ không chỉ JRE (Runtime Environment).

### Cấu hình biến môi trường (Windows)

```bash
# Thêm vào System Environment Variables
JAVA_HOME = C:\Program Files\Java\jdk-21
PATH = %JAVA_HOME%\bin;%PATH%
```

> **📝 Giải thích chi tiết cấu hình:**
> * `JAVA_HOME`: Biến hệ thống định nghĩa đường dẫn gốc (root path) đến thư mục cài đặt JDK. Nhiều công cụ build (như Maven, Gradle) và IDE sẽ tìm biến này để biết Java nằm ở đâu.
> * `%JAVA_HOME%\bin`: Trỏ trực tiếp vào thư mục chứa các file thực thi quan trọng như `java.exe`, `javac.exe`. Việc đưa đường dẫn này vào `PATH` giúp bạn chạy các lệnh Java từ bất kỳ thư mục nào trên Command Prompt hoặc PowerShell mà không cần gõ đầy đủ đường dẫn thư mục cài đặt.

### Cấu hình biến môi trường (Linux/macOS)

```bash
# Thêm vào ~/.bashrc hoặc ~/.zshrc
export JAVA_HOME=/usr/lib/jvm/java-21-openjdk
export PATH=$JAVA_HOME/bin:$PATH
```

> **📝 Giải thích chi tiết cấu hình:**
> * `export JAVA_HOME=...`: Khai báo biến môi trường trong phiên làm việc hiện tại, trỏ tới thư mục cài đặt Java trên Unix/Linux.
> * `export PATH=$JAVA_HOME/bin:$PATH`: Thêm thư mục binary (`bin`) của Java lên đầu danh sách tìm kiếm của biến `PATH` hệ thống. Dấu `:` đóng vai trò là ký tự phân tách đường dẫn trong Linux/macOS.

## 2. Cài đặt IDE – IntelliJ IDEA

> **🔍 WHAT:** IntelliJ IDEA là môi trường phát triển tích hợp (IDE) mạnh mẽ nhất hiện nay dành cho Java, được phát triển bởi JetBrains.

> **💡 WHY:** IDE giúp lập trình viên code nhanh hơn, phát hiện lỗi sớm hơn, tích hợp sẵn debugger, refactoring tool và hỗ trợ Spring Boot rất tốt – tiết kiệm rất nhiều thời gian so với dùng text editor thông thường.
>
> **⚙️ HOW:** Tải và cài đặt IntelliJ IDEA (bản Community miễn phí hoặc Ultimate trả phí), sau đó mở project Java/Maven/Gradle và IDE sẽ tự động nhận diện cấu hình.
>
> **📍 WHEN/WHERE:** Dùng hàng ngày trong suốt quá trình phát triển – từ viết code, debug, chạy test cho đến quản lý dependencies trong mọi dự án Java.

### Các bước cài đặt

1. Truy cập [https://www.jetbrains.com/idea/download/](https://www.jetbrains.com/idea/download/)
2. Chọn phiên bản:
   - **Community Edition** (miễn phí): Đủ dùng cho Java cơ bản
   - **Ultimate Edition** (trả phí/30 ngày trial): Hỗ trợ Spring Boot, Databases, Web frameworks

## 3. Cài đặt Maven / Gradle

> **🔍 WHAT:** Maven và Gradle là các công cụ quản lý build và dependency (thư viện) cho dự án Java – tương tự như `npm` trong Node.js hoặc `pip` trong Python.
>
> **💡 WHY:** Dự án Java thực tế sử dụng rất nhiều thư viện bên ngoài (Spring, Hibernate, v.v.). Maven/Gradle tự động tải, quản lý phiên bản và build project, giúp tránh việc quản lý jar file thủ công.
>
> **⚙️ HOW:** Maven dùng file `pom.xml` để khai báo dependencies và cấu hình build; Gradle dùng file `build.gradle`. Khi chạy lệnh build, tool sẽ tự tải thư viện từ Maven Central Repository về máy.
>
> **📍 WHEN/WHERE:** Dùng ngay khi tạo project mới và trong suốt vòng đời dự án – mỗi lần thêm thư viện mới, chạy test hoặc đóng gói ứng dụng để deploy.

### Cài đặt Maven

```bash
# Kiểm tra Maven đã có chưa (IntelliJ thường tích hợp sẵn)
mvn -version

# Cài trên Ubuntu/Debian
sudo apt install maven

# Cài trên macOS
brew install maven
```

> **📝 Giải thích chi tiết lệnh:**
> * `mvn -version`: Kiểm tra phiên bản Maven hiện tại đang được cài trên hệ thống và hiển thị cả phiên bản Java mà Maven đang sử dụng để chạy.

### Cài đặt Gradle

```bash
# Kiểm tra Gradle
gradle -version

# Cài trên Ubuntu/Debian
sudo apt install gradle

# Cài trên macOS
brew install gradle
```

> **📝 Giải thích chi tiết lệnh:**
> * `gradle -version`: Kiểm tra phiên bản Gradle hiện tại của hệ thống. Gradle là một công cụ quản lý dependency dựa trên DSL (Domain Specific Language), cấu hình linh hoạt và tốc độ build vượt trội hơn Maven nhờ cơ chế Incremental Build (chỉ build phần thay đổi).

### So sánh Maven vs Gradle

| Tiêu chí | Maven | Gradle |
|----------|-------|--------|
| File cấu hình | `pom.xml` (XML) | `build.gradle` (Groovy/Kotlin) |
| Tốc độ | Chậm hơn | Nhanh hơn (có cache) |
| Phổ biến | Rất phổ biến | Phổ biến (Android, Kotlin) |
| Học | Dễ hơn | Linh hoạt hơn |

> **Khuyến nghị:** Dùng **Maven** nếu mới bắt đầu, **Gradle** nếu làm Android hoặc Kotlin.

## 4. Cài đặt Database

> **🔍 WHAT:** Database (cơ sở dữ liệu) là nơi ứng dụng lưu trữ và truy xuất dữ liệu một cách có tổ chức. Hai loại phổ biến nhất trong Java Backend là PostgreSQL (quan hệ) và MySQL (quan hệ).
>
> **💡 WHY:** Hầu hết mọi ứng dụng backend đều cần lưu trữ dữ liệu lâu dài. Cài đặt database cục bộ giúp bạn phát triển và test ứng dụng mà không cần kết nối cloud hay server từ xa.
>
> **⚙️ HOW:** Cài đặt database server trên máy local, tạo database và user, sau đó kết nối từ ứng dụng Java thông qua JDBC URL, username và password được cấu hình trong `application.properties`.
>
> **📍 WHEN/WHERE:** Cần thiết ngay khi bắt đầu xây dựng tầng data của ứng dụng – khi làm việc với Spring Data JPA, Hibernate, hoặc bất kỳ tính năng nào cần persistence.

### PostgreSQL (Khuyến nghị)

```bash
# Ubuntu/Debian
sudo apt install postgresql postgresql-contrib
sudo systemctl start postgresql

# macOS
brew install postgresql
brew services start postgresql

# Tạo database
psql -U postgres
CREATE DATABASE myapp_db;
CREATE USER myapp_user WITH PASSWORD 'password123';
GRANT ALL PRIVILEGES ON DATABASE myapp_db TO myapp_user;
```

> **📝 Giải thích chi tiết lệnh database:**
> * `psql -U postgres`: Kết nối tới Postgres Database Server bằng Terminal thông qua tài khoản admin mặc định `postgres`.
> * `CREATE DATABASE myapp_db;`: Tạo một vùng chứa dữ liệu (Database) tên là `myapp_db`.
> * `CREATE USER myapp_user WITH PASSWORD 'password123';`: Tạo một tài khoản người dùng mới chuyên biệt cho ứng dụng để tăng tính bảo mật, tránh dùng tài khoản superuser (root/postgres) trong mã nguồn.
> * `GRANT ALL PRIVILEGES ON DATABASE...`: Cấp toàn quyền (đọc, ghi, sửa, xóa cấu trúc bảng) của database `myapp_db` cho user vừa tạo.

### MySQL

```bash
# Ubuntu/Debian
sudo apt install mysql-server
sudo systemctl start mysql

# macOS
brew install mysql
brew services start mysql

# Bảo mật và tạo user
mysql_secure_installation
mysql -u root -p
CREATE DATABASE myapp_db;
CREATE USER 'myapp_user'@'localhost' IDENTIFIED BY 'password123';
GRANT ALL PRIVILEGES ON myapp_db.* TO 'myapp_user'@'localhost';
```

> **📝 Giải thích chi tiết lệnh database:**
> * `mysql_secure_installation`: Chạy một script tiện ích của MySQL để cấu hình bảo mật hệ thống: thiết lập mật khẩu root, xóa user ẩn danh, tắt login từ xa.
> * `CREATE USER 'myapp_user'@'localhost'...`: Tạo tài khoản người dùng mới giới hạn chỉ được phép truy cập MySQL từ chính máy cục bộ (`localhost`) để ngăn ngừa tấn công mạng từ bên ngoài.

## 5. Cài đặt Docker

> **🔍 WHAT:** Docker là nền tảng container hóa, cho phép đóng gói ứng dụng và tất cả dependencies của nó vào một "container" có thể chạy nhất quán trên mọi môi trường.
>
> **💡 WHY:** Docker giải quyết vấn đề "chạy được trên máy tôi" – đảm bảo ứng dụng hoạt động giống nhau từ máy dev đến server production. Ngoài ra, có thể dùng Docker để chạy database, Redis, v.v. mà không cần cài trực tiếp.
>
> **⚙️ HOW:** Viết `Dockerfile` để định nghĩa cách build image, dùng `docker-compose.yml` để orchestrate nhiều service cùng lúc. Lệnh `docker run` khởi tạo container từ image.
>
> **📍 WHEN/WHERE:** Dùng khi cần chạy services phụ trợ (DB, Redis, Kafka) trong dev; bắt buộc khi deploy lên cloud hoặc Kubernetes trong production.

### Cài đặt Docker Desktop

1. Truy cập [https://www.docker.com/products/docker-desktop/](https://www.docker.com/products/docker-desktop/)
2. Tải và cài Docker Desktop cho hệ điều hành của bạn
3. Kiểm tra cài đặt:

```bash
docker --version
docker compose version
```

> **📝 Giải thích chi tiết lệnh:**
> * `docker --version`: Kiểm tra phiên bản Docker Engine cục bộ.
> * `docker compose version`: Kiểm tra phiên bản của công cụ Compose dùng để quản lý các ứng dụng đa container.

### Chạy PostgreSQL bằng Docker (thay thế cài đặt thủ công)

```yaml
# docker-compose.yml
version: '3.8'
services:
  postgres:
    image: postgres:15
    container_name: myapp_postgres
    environment:
      POSTGRES_DB: myapp_db
      POSTGRES_USER: myapp_user
      POSTGRES_PASSWORD: password123
    ports:
      - "5432:5432"
    volumes:
      - postgres_data:/var/lib/postgresql/data

volumes:
  postgres_data:
```

> **📝 Giải thích chi tiết cấu hình YAML:**
> * `version: '3.8'`: Chỉ định phiên bản cấu trúc của file Docker Compose.
> * `image: postgres:15`: Tải image Postgres bản 15 chính thức từ kho lưu trữ Docker Hub.
> * `container_name: myapp_postgres`: Đặt tên tường minh cho container để quản lý dễ dàng thay vì Docker tự sinh tên ngẫu nhiên.
> * `environment`: Thiết lập các biến môi trường nội bộ trong container để tự động cấu hình database name, username và password lúc khởi tạo.
> * `ports: - "5432:5432"`: Ánh xạ (forward) cổng mạng từ máy vật lý (cổng `5432` bên trái) vào cổng dịch vụ bên trong container (cổng `5432` bên phải).
> * `volumes`: Khai báo cơ chế lưu trữ dữ liệu bền vững. `postgres_data:/var/lib/postgresql/data` giúp ánh xạ dữ liệu database từ container ra thư mục ngoài máy thật. Khi xóa container, dữ liệu của bạn vẫn an toàn, không bị mất.

```bash
# Khởi động
docker compose up -d

# Dừng
docker compose down
```

> **📝 Giải thích chi tiết lệnh:**
> * `docker compose up -d`: Tạo và khởi chạy các container được định nghĩa trong file `docker-compose.yml`. Cờ `-d` (detached mode) giúp chạy ngầm ứng dụng dưới background để giải phóng Terminal cho bạn gõ lệnh khác.
> * `docker compose down`: Dừng các container đang chạy và giải phóng hoàn toàn tài nguyên hệ thống (network, container...) liên quan tới file compose đó.

## 6. Cài đặt Git

> **🔍 WHAT:** Git là hệ thống quản lý phiên bản phân tán (distributed version control system), theo dõi mọi thay đổi trong source code theo thời gian.
>
> **💡 WHY:** Git là công cụ không thể thiếu trong phát triển phần mềm chuyên nghiệp – giúp làm việc nhóm hiệu quả, rollback khi có lỗi, quản lý nhiều tính năng song song qua branching.
>
> **⚙️ HOW:** Git lưu lịch sử thay đổi dưới dạng các "commit". Bạn dùng `git add` để stage thay đổi, `git commit` để lưu snapshot, `git push/pull` để đồng bộ với remote repository (GitHub, GitLab).
>
> **📍 WHEN/WHERE:** Dùng ngay từ ngày đầu dự án và liên tục trong suốt quá trình phát triển – mỗi khi hoàn thành một tính năng hay fix một bug đều cần commit.

### Cài đặt Git

```bash
# Ubuntu/Debian
sudo apt install git

# macOS
brew install git
# hoặc cài Xcode Command Line Tools: xcode-select --install

# Windows: Tải từ https://git-scm.com/download/win
```

### Cấu hình Git lần đầu

```bash
git config --global user.name "Tên của bạn"
git config --global user.email "email@example.com"
git config --global core.editor "code"  # Dùng VS Code làm editor mặc định

# Kiểm tra cấu hình
git config --list
```

> **📝 Giải thích chi tiết cấu hình:**
> * `git config --global user.name` và `user.email`: Khai báo thông tin định danh tác giả. Mọi commit bạn tạo ra sẽ đính kèm thông tin này để đồng nghiệp biết ai là người viết code đó. Cờ `--global` áp dụng cài đặt này cho tất cả dự án Git trên máy tính của bạn.
> * `git config --list`: Liệt kê tất cả các cấu hình hiện tại mà Git đang ghi nhận.

### Các lệnh Git cơ bản

```bash
git init                    # Khởi tạo repo mới
git clone <url>             # Clone repo từ remote
git status                  # Xem trạng thái thay đổi
git add .                   # Stage tất cả thay đổi
git commit -m "message"     # Commit với message
git push origin main        # Push lên remote
git pull origin main        # Pull về từ remote
git branch feature/login    # Tạo branch mới
git checkout feature/login  # Chuyển sang branch
git merge feature/login     # Merge branch vào nhánh hiện tại
```

> **📝 Giải thích chi tiết lệnh Git:**
> * `git init`: Khởi tạo một kho lưu trữ Git cục bộ (Local Repository) rỗng trong thư mục hiện tại.
> * `git status`: Xem các file đã được chỉnh sửa, các file mới chưa được theo dõi (untracked) hoặc các file đang nằm trong khu vực chuẩn bị commit (staging area).
> * `git add .`: Đưa toàn bộ các thay đổi hiện tại từ thư mục làm việc vào vùng đệm Staging Area để chuẩn bị cho việc đóng gói commit.
> * `git commit -m "message"`: Đóng gói (snapshot) các thay đổi đang nằm ở Staging Area vào lịch sử Git cục bộ kèm theo lời giải thích ngắn gọn về thay đổi đó (`-m`).
> * `git push origin main`: Đẩy các commit cục bộ lên máy chủ Git từ xa (Remote Repository như GitHub) lên nhánh `main`.

## 7. Tạo Project Spring Boot đầu tiên

> **🔍 WHAT:** Spring Boot là framework Java phổ biến nhất để xây dựng ứng dụng backend, cung cấp cấu hình tự động và tích hợp sẵn hàng trăm thư viện – cho phép tạo REST API production-ready chỉ trong vài phút.
>
> **💡 WHY:** Spring Boot loại bỏ hầu hết cấu hình boilerplate phức tạp của Spring truyền thống, giúp bạn tập trung vào business logic thay vì cấu hình hạ tầng.
>
> **⚙️ HOW:** Dùng Spring Initializr (web hoặc trong IntelliJ) để sinh ra project skeleton với các dependency đã chọn. Project dùng Maven/Gradle, có thể chạy ngay bằng `mvn spring-boot:run` hoặc `./gradlew bootRun`.
>
> **📍 WHEN/WHERE:** Đây là bước đầu tiên của mỗi dự án backend Java mới – tạo project structure chuẩn trước khi bắt đầu code business logic.

### Sử dụng Spring Initializr

1. Truy cập [https://start.spring.io/](https://start.spring.io/)
2. Cấu hình:
   - **Project:** Maven
   - **Language:** Java
   - **Spring Boot:** 3.x.x (mới nhất)
   - **Packaging:** Jar
   - **Java:** 21
3. Thêm Dependencies:
   - `Spring Web` – Tạo REST API
   - `Spring Data JPA` – Tương tác Database
   - `PostgreSQL Driver` – Kết nối PostgreSQL
   - `Lombok` – Giảm boilerplate code
   - `Spring Boot DevTools` – Hot reload khi dev
4. Click **Generate** → tải file `.zip` → giải nén và mở bằng IntelliJ

### Cấu trúc Project

```
my-app/
├── src/
│   ├── main/
│   │   ├── java/
│   │   │   └── com/example/myapp/
```

### Cấu hình application.properties

```properties
# Server
server.port=8080

# Database
spring.datasource.url=jdbc:postgresql://localhost:5432/myapp_db
spring.datasource.username=myapp_user
spring.datasource.password=password123
spring.datasource.driver-class-name=org.postgresql.Driver

# JPA / Hibernate
spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true
spring.jpa.database-platform=org.hibernate.dialect.PostgreSQLDialect
```

> **📝 Giải thích chi tiết thuộc tính cấu hình:**
> * `server.port=8080`: Chỉ định cổng cổng mạng mà máy chủ Spring Boot (nhúng sẵn Tomcat) sẽ lắng nghe kết nối HTTP. Mặc định là `8080`.
> * `spring.datasource.url`: Chuỗi kết nối JDBC định nghĩa giao thức kết nối, địa chỉ server (`localhost`), cổng mạng (`5432`) và database mục tiêu (`myapp_db`).
> * `spring.jpa.hibernate.ddl-auto=update`: Cấu hình chiến lược tự động sinh cấu trúc bảng từ code Java Entity. Giá trị `update` giúp Hibernate tự động tạo bảng mới hoặc sửa đổi cấu trúc bảng đang có mà không xóa đi dữ liệu cũ khi ứng dụng khởi chạy.
> * `spring.jpa.show-sql=true`: Hiển thị tất cả các câu lệnh SQL mà Hibernate tự động sinh ra trên Terminal Console để lập trình viên dễ theo dõi, gỡ lỗi.
> * `spring.jpa.properties.hibernate.format_sql=true`: Format lại các câu lệnh SQL hiển thị trên Console cho thẳng hàng, dễ đọc.

### Chạy ứng dụng

```bash
# Bằng Maven
./mvnw spring-boot:run

# Bằng Gradle
./gradlew bootRun

# Kiểm tra ứng dụng đang chạy
curl http://localhost:8080
```

> **📝 Giải thích chi tiết lệnh:**
> * `./mvnw spring-boot:run`: Sử dụng tiện ích Maven Wrapper (file `./mvnw` có sẵn ở thư mục gốc project) để khởi động ứng dụng Spring Boot. Lợi ích của wrapper là nó tự tải đúng phiên bản Maven được chỉ định trong dự án mà không bắt buộc máy dev phải cài trước Maven.
> * `curl http://localhost:8080`: Gửi một HTTP Request rỗng tới server local đang chạy trên cổng 8080 để kiểm tra kết nối dịch vụ trực tiếp từ Terminal.
