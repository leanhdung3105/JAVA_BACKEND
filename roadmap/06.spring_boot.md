# 06. Spring Framework & Spring Boot

> **Mục tiêu:** Hiểu và xây dựng được ứng dụng backend hoàn chỉnh với Spring Boot.

---

## 1. Spring Framework – Tổng quan

> **🔍 WHAT:** Spring Framework là framework Java toàn diện nhất, cung cấp IoC Container (quản lý object), AOP, data access, web MVC. Spring Boot là lớp trên cùng tự động cấu hình Spring.
>
> **💡 WHY:** Spring giải quyết các vấn đề phức tạp (DI, transaction management, security, data access) theo cách chuẩn hóa. Spring Boot loại bỏ 90% configuration thủ công – tạo được REST API production-ready trong vài phút.
>
> **⚙️ HOW:** Spring dùng IoC Container để quản lý lifecycle của Bean (object). `@SpringBootApplication` kích hoạt auto-configuration dựa trên dependencies có trong classpath. Không cần XML config nữa.
>
> **📍 WHEN/WHERE:** Nền tảng của mọi dự án trong roadmap này – Spring Boot là runtime environment. Mọi annotation (@Service, @Repository, @Controller) đều cần Spring Container để hoạt động.

```
Spring Ecosystem
├── Spring Core (IoC, DI)          ← Nền tảng
├── Spring MVC / WebFlux           ← Web layer
├── Spring Data (JPA, Redis...)    ← Data access
├── Spring Security                ← Bảo mật
├── Spring Boot (auto-config)      ← Productivity
└── Spring Cloud (microservices)   ← Distributed systems
```

```java
// Các Spring Bean annotations
@Component   // Generic bean
@Service     // Business logic
@Repository  // Data access (+ exception translation)
@Controller / @RestController  // Web layer
@Configuration + @Bean         // Java config
```

> **📝 Giải thích chi tiết khái niệm:**
> * **Bean**: Là một đối tượng (object) được khởi tạo, quản lý vòng đời và tiêm các dependency bởi Spring IoC (Inversion of Control) Container chứ không phải do bạn tự khởi tạo bằng từ khóa `new` thủ công.
> * `@Component`: Annotation gốc để đánh dấu một lớp là một Spring Bean. Spring Component Scanner sẽ tự động tìm thấy và đưa nó vào quản lý trong IoC Container.
> * `@Service`: Một dạng chuyên biệt của `@Component`, dùng để đánh dấu lớp thuộc tầng **Nghiệp vụ (Business Layer / Service Layer)**. Về mặt kỹ thuật nó giống `@Component`, nhưng giúp làm tăng tính ngữ nghĩa rõ ràng của code.
> * `@Repository`: Dùng ở tầng **Truy cập Dữ liệu (Data Access Layer)**. Ngoài việc đánh dấu bean, nó còn tự động kích hoạt tính năng **Exception Translation** – tự động bắt các lỗi DB cấp thấp của JDBC/SQL và dịch sang dạng ngoại lệ thân thiện hơn của Spring (`DataAccessException`).
> * `@RestController`: Kết hợp giữa `@Controller` và `@ResponseBody`. Dùng cho tầng **Web (Presentation Layer)** để xử lý HTTP requests. Toàn bộ dữ liệu trả về từ các phương thức sẽ tự động được chuyển đổi sang định dạng JSON/XML để phản hồi về Client, thay vì trả về các trang HTML truyền thống.
> * `@Configuration` & `@Bean`: Dùng để cấu hình các Bean theo cách thủ công thông qua code Java thay vì cấu hình tự động (Component Scanning). Rất hữu ích khi cần cấu hình các thư viện từ bên thứ 3.

## 2. Tạo Spring Boot Project

> **🔍 WHAT:** Spring Boot project là cấu trúc thư mục chuẩn với `pom.xml`/`build.gradle`, entry point `main()`, và tổ chức package theo layer (controller/service/repository/model).
>
> **💡 WHY:** Cấu trúc đúng giúp team dễ navigate code, tách biệt trách nhiệm rõ ràng. Convention over configuration – tuân theo cấu trúc Spring chuẩn giúp tận dụng auto-configuration tốt nhất.
>
> **⚙️ HOW:** Dùng [Spring Initializr](https://start.spring.io/) để generate project skeleton. Chọn dependencies phù hợp (Web, JPA, Security...). Import vào IntelliJ và chạy ngay.
>
> **📍 WHEN/WHERE:** Bước đầu tiên của mỗi dự án mới. Cấu trúc package được giữ nguyên suốt vòng đời dự án và là quy ước để mọi developer hiểu project nhanh chóng.

```
src/main/java/com/example/myapp/
├── MyAppApplication.java           ← Entry point (@SpringBootApplication)
├── config/                         ← Cấu hình (Security, Swagger, Redis...)
├── controller/                     ← HTTP request handlers (@RestController)
├── service/                        ← Business logic
│   ├── UserService.java (interface)
│   └── impl/UserServiceImpl.java
├── repository/                     ← Database access (@Repository)
├── model/entity/                   ← JPA Entities (@Entity)
├── dto/                            ← Data Transfer Objects
│   ├── request/CreateUserRequest.java
│   └── response/UserResponse.java
├── exception/                      ← Custom exceptions + GlobalExceptionHandler
└── util/                           ← Helper/utility classes
```

```java
@SpringBootApplication  // = @Configuration + @ComponentScan + @EnableAutoConfiguration
public class MyAppApplication {
    public static void main(String[] args) {
        SpringApplication.run(MyAppApplication.class, args);
    }
}
```

> **📝 Giải thích chi tiết code:**
> * `@SpringBootApplication`: Một Annotation siêu cấp cực kỳ mạnh mẽ, là sự kết hợp của 3 annotation cốt lõi:
>   * `@SpringBootConfiguration` (tương đương `@Configuration`): Biến class này thành nơi cấu hình dự án.
>   * `@EnableAutoConfiguration`: Kích hoạt cơ chế **Tự động cấu hình thông minh** của Spring Boot. Dựa vào các file `.jar` thư viện bạn khai báo trong `pom.xml` (classpath), Spring Boot sẽ đoán và tự cấu hình sẵn các thành phần tương ứng (Ví dụ: Thấy jar `postgresql` + `spring-data-jpa` -> tự động cấu hình DataSource, Connection Pool và Entity Manager).
>   * `@ComponentScan`: Chỉ thị cho Spring quét toàn bộ thư mục hiện tại cùng các thư mục con của nó để tìm kiếm các class có gắn `@Component`, `@Service`, `@Repository`, `@RestController`... nhằm tự động khởi tạo thành Bean. **Lưu ý:** Lớp entry point phải đặt ở package gốc để quét được toàn bộ dự án.
> * `SpringApplication.run(MyAppApplication.class, args)`: Dòng lệnh khởi chạy toàn bộ ứng dụng Spring Boot. Nó sẽ khởi động IoC Container, chạy Component Scanner, kích hoạt Auto-Configuration, và khởi tạo một máy chủ web nhúng Tomcat chạy trên cổng 8080.

## 3. application.yml

> **🔍 WHAT:** `application.yml` (hoặc `application.properties`) là file cấu hình trung tâm của Spring Boot – nơi khai báo port, database URL, JWT secret, logging level và mọi cấu hình ứng dụng.
>
> **💡 WHY:** Tách biệt cấu hình khỏi code – thay đổi DB URL không cần recompile. Dễ override cho từng môi trường (dev/staging/prod) qua profiles hoặc environment variables.
>
> **⚙️ HOW:** YAML format với cấu trúc phân cấp dùng dấu thụt lề. Spring Boot tự đọc file này khi khởi động. Giá trị có thể tham chiếu env variable: `${ENV_VAR:default_value}`.
>
> **📍 WHEN/WHERE:** Ở `src/main/resources/`. Mỗi profile có file riêng (`application-dev.yml`, `application-prod.yml`). Sensitive data (password, secret key) KHÔNG hardcode – dùng env variable.

```yaml
spring:
  application:
    name: my-app

  datasource:
    url: jdbc:postgresql://localhost:5432/mydb
    username: ${DB_USERNAME:myuser}     # env var với default
    password: ${DB_PASSWORD:mypassword}

  jpa:
    hibernate:
      ddl-auto: validate    # update | create | create-drop | validate | none
    show-sql: false         # true khi dev, false khi prod
    properties:
      hibernate:
        format_sql: true

server:
  port: 8080

logging:
  level:
    com.example.myapp: DEBUG   # DEBUG khi dev

app:
  jwt:
    secret: ${JWT_SECRET}
    expiration: 86400000       # 24 giờ (ms)
```

> **📝 Giải thích chi tiết cấu hình YAML:**
> * `spring.datasource.username: ${DB_USERNAME:myuser}`: Cơ chế lấy cấu hình động. Spring Boot sẽ tìm biến môi trường hệ thống có tên là `DB_USERNAME`. Nếu không tìm thấy, nó sẽ tự động sử dụng giá trị mặc định đứng sau dấu hai chấm là `myuser`. Điều này rất hữu ích khi deploy Docker hoặc CI/CD.
> * `ddl-auto: validate`: Chiến lược kiểm tra tính khớp nối giữa các class `@Entity` trong Java và cấu trúc bảng thực tế trong Database. Tránh dùng `update` hoặc `create-drop` trên môi trường Production để bảo toàn dữ liệu thật, giá trị `validate` được khuyến nghị dùng vì nó chỉ kiểm tra cấu trúc, nếu sai lệch sẽ dừng khởi động ứng dụng để cảnh báo dev chứ không can thiệp xóa hay đổi dữ liệu.
> * `com.example.myapp: DEBUG`: Cấu hình cấp độ ghi log (Logging level). Mức `DEBUG` sẽ hiển thị rất nhiều thông tin chi tiết của luồng code nội bộ trên console, hỗ trợ đắc lực khi dev. Khi deploy Production nên chuyển về mức `INFO` hoặc `WARN` để tránh ghi log quá nhiều làm chậm hệ thống.

## 4. Profiles (môi trường)

> **🔍 WHAT:** Spring Profiles cho phép định nghĩa cấu hình khác nhau cho từng môi trường (development, testing, production) và kích hoạt đúng profile khi chạy.
>
> **💡 WHY:** Dev cần log SQL, dùng H2 in-memory; Production cần kết nối DB thật, tắt log. Profiles giúp quản lý sự khác biệt này mà không cần sửa code khi deploy.
>
> **⚙️ HOW:** Tạo file `application-{profile}.yml`, kích hoạt qua `spring.profiles.active=dev` trong config hoặc `-Dspring.profiles.active=prod` khi chạy. Bean có thể dùng `@Profile("dev")` để chỉ active với profile đó.
>
> **📍 WHEN/WHERE:** Bắt buộc trong dự án thực tế – ít nhất 2 profiles: `dev` (localhost) và `prod` (server). CI/CD pipeline set profile qua environment variable khi deploy.

```yaml
# application-dev.yml
spring:
  datasource:
    url: jdbc:postgresql://localhost:5432/mydb_dev
  jpa:
    show-sql: true
    hibernate:
      ddl-auto: update

---
# application-prod.yml
spring:
  datasource:
    url: jdbc:postgresql://prod-server:5432/mydb
  jpa:
    show-sql: false
    hibernate:
      ddl-auto: validate  # không auto-migrate production
```

```bash
# Kích hoạt profile
java -jar app.jar --spring.profiles.active=prod

# Hoặc env var:
export SPRING_PROFILES_ACTIVE=prod
```

> **📝 Giải thích chi tiết cấu hình và lệnh:**
> * `application-{profile}.yml`: Quy ước đặt tên file của Spring Boot. Khi bạn kích hoạt profile `prod`, Spring Boot sẽ tự động tải các cấu hình trong file `application-prod.yml` để đè lên các cấu hình mặc định trong file `application.yml`.
> * `java -jar app.jar --spring.profiles.active=prod`: Lệnh chạy ứng dụng Java dạng gói đóng sẵn (`.jar`), truyền trực tiếp tham số cấu hình kích hoạt môi trường Production vào ứng dụng lúc khởi động.
> * `export SPRING_PROFILES_ACTIVE=prod`: Khai báo biến môi trường hệ thống. Spring Boot sẽ tự động bắt biến này để kích hoạt profile tương ứng, phương pháp này được dùng phổ biến nhất khi triển khai dự án lên Docker hoặc Kubernetes.

## 5. Dependency Injection Patterns

> **🔍 WHAT:** Dependency Injection (DI) là kỹ thuật cung cấp dependencies (các object phụ thuộc) cho một object từ bên ngoài thay vì để object tự tạo – Spring Container làm điều này tự động.
>
> **💡 WHY:** DI giảm coupling giữa các class, giúp code dễ test (có thể inject mock thay vì real dependency), dễ swap implementation và tuân theo nguyên tắc DIP của SOLID.
>
> **⚙️ HOW:** 3 kiểu: Constructor injection (recommended), Setter injection, Field injection (`@Autowired`). Constructor injection buộc khai báo dependency rõ ràng, hỗ trợ immutability và dễ viết test nhất.
>
> **📍 WHEN/WHERE:** Mọi Spring Bean cần dependency khác đều dùng DI. Trong thực tế: Controller inject Service, Service inject Repository. Dùng `@RequiredArgsConstructor` (Lombok) để tự sinh constructor.

```java
// ✅ Constructor Injection – BEST PRACTICE
@Service
@RequiredArgsConstructor  // Lombok tự sinh constructor cho các final field
public class OrderService {
    private final OrderRepository orderRepository;  // final – immutable
    private final UserService userService;
    private final EmailService emailService;
}

// Tương đương với việc viết tay:
@Service
public class OrderService {
    private final OrderRepository orderRepository;
    private final UserService userService;

    public OrderService(OrderRepository orderRepository, UserService userService) {
        this.orderRepository = orderRepository;
        this.userService = userService;
    }
}

// ❌ Field Injection – KHÔNG khuyến nghị (khó test, không immutable)
@Service
public class OrderService {
    @Autowired private OrderRepository orderRepository; // tránh dùng
}
```

> **📝 Giải thích chi tiết code:**
> * `private final`: Việc khai báo thuộc tính là `final` (bất biến) ép buộc thuộc tính đó phải được gán giá trị ngay trong hàm khởi tạo Constructor và không thể thay đổi sau đó. Điều này đảm bảo an toàn đa luồng (Thread-safe) và ngăn ngừa lỗi null pointer bất ngờ khi chạy.
> * `@RequiredArgsConstructor`: Annotation của Lombok sẽ tự động quét toàn bộ các thuộc tính khai báo là `final` hoặc `@NonNull` trong class để tạo ra một Constructor tương ứng. Giúp code cực kỳ sạch đẹp, giảm boilerplate code.
> * **Tại sao chọn Constructor Injection thay vì `@Autowired` trên thuộc tính (Field Injection)?**
>   1. **Dễ viết Unit Test**: Bạn có thể dễ dàng khởi tạo `new OrderService(mockRepo, mockUserService)` trong Unit Test mà không cần chạy cả Spring Container cồng kềnh hay phải dùng đến cơ chế reflection để tiêm mock dependency.
>   2. **Tránh lỗi tuần hoàn (Circular Dependency)**: Spring Boot có thể phát hiện lỗi phụ thuộc vòng tròn giữa các bean ngay khi khởi chạy ứng dụng (ví dụ: A cần B, B cần A), giúp sửa lỗi sớm thay vì xảy ra lỗi lúc runtime.
>   3. **Đảm bảo tính bất biến (Immutability)**: Như đã nói, thuộc tính có thể đặt là `final` – điều không thể làm được với `@Autowired` trực tiếp trên field.

## 6. Bean Configuration

> **🔍 WHAT:** `@Configuration` class là nơi khai báo custom Bean bằng code Java thay vì để Spring auto-detect – dùng khi cần tùy chỉnh cách tạo bean (như cấu hình ObjectMapper, DataSource, HttpClient).
>
> **💡 WHY:** Một số bean không thể dùng `@Component` (như thư viện bên thứ 3), hoặc cần cấu hình phức tạp trước khi tạo – `@Bean` method giải quyết điều này một cách rõ ràng và type-safe.
>
> **⚙️ HOW:** Tạo class `@Configuration`, khai báo method `@Bean` trả về object cần tạo. Spring sẽ gọi method này và quản lý lifecycle của object đó. `@ConfigurationProperties` để bind config từ yml vào POJO.
>
> **📍 WHEN/WHERE:** Cấu hình `ObjectMapper` (serialize/deserialize JSON), `ModelMapper`/`MapStruct`, `WebClient`, `PasswordEncoder`, Security config, CORS config. Mỗi concern nên có file config riêng trong package `config/`.

```java
@Configuration
public class AppConfig {

    // Custom ObjectMapper để handle Java 8 date/time
    @Bean
    public ObjectMapper objectMapper() {
        ObjectMapper mapper = new ObjectMapper();
        mapper.registerModule(new JavaTimeModule());
        mapper.disable(SerializationFeature.WRITE_DATES_AS_TIMESTAMPS);
        return mapper;
    }

    // PasswordEncoder bean
    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }
}

// @ConfigurationProperties – bind config từ yml vào class
@Component
@ConfigurationProperties(prefix = "app.jwt")
@Data
public class JwtProperties {
    private String secret;      // app.jwt.secret
    private long expiration;    // app.jwt.expiration
}
```

> **📝 Giải thích chi tiết code:**
> * `@Configuration`: Đánh dấu class `AppConfig` đóng vai trò là một nơi định nghĩa cấu hình. Spring Container khi quét qua class này sẽ thực hiện đăng ký các Bean được định nghĩa bên trong nó.
> * `@Bean`: Đánh dấu trên phương thức. Giá trị trả về của phương thức này (đối tượng `ObjectMapper` hoặc `PasswordEncoder` được khởi tạo bằng `new`) sẽ được Spring đăng ký thành một Bean trong IoC Container.
> * `mapper.registerModule(new JavaTimeModule())`: Ví dụ cấu hình nâng cao cho thư viện ObjectMapper. Nó đăng ký module xử lý kiểu dữ liệu ngày tháng của Java 8 (`LocalDateTime`, `LocalDate`...) để chuyển đổi mượt mà sang định dạng ISO-8601 thay vì in ra dạng chuỗi số dài dòng.
> * `@ConfigurationProperties(prefix = "app.jwt")`: Tính năng tuyệt vời giúp ánh xạ (bind) trực tiếp các giá trị cấu hình có tiền tố `app.jwt` trong file `application.yml` vào các thuộc tính tương ứng của class `JwtProperties` (`secret`, `expiration`) một cách tự động và an toàn (type-safe).

## 7. Event System

> **🔍 WHAT:** Spring Event System là cơ chế publish-subscribe nội bộ: một component publish event, các component khác listen và xử lý – decoupled, không cần biết nhau trực tiếp.
>
> **💡 WHY:** Giảm coupling giữa các service. Ví dụ: UserService chỉ cần publish `UserRegisteredEvent` mà không cần biết có bao nhiêu listener (email service, analytics, audit log...). Dễ thêm listener mới mà không sửa code cũ (Open/Closed Principle).
>
> **⚙️ HOW:** Tạo event class kế thừa `ApplicationEvent`. Inject `ApplicationEventPublisher` để publish. Dùng `@EventListener` (hoặc `@TransactionalEventListener`) để listen. Thêm `@Async` để xử lý bất đồng bộ.
>
> **📍 WHEN/WHERE:** Gửi email chào mừng sau đăng ký; ghi audit log; cập nhật cache khi data thay đổi; thông báo real-time. Phù hợp cho side effects không thuộc core business logic.

```java
// Event class
public class UserRegisteredEvent extends ApplicationEvent {
    private final User user;
    public UserRegisteredEvent(Object source, User user) {
        super(source);
        this.user = user;
    }
    public User getUser() { return user; }
}

// Publisher
@Service @RequiredArgsConstructor
public class UserService {
    private final ApplicationEventPublisher eventPublisher;

    public User register(CreateUserRequest request) {
        User user = createUser(request);
        eventPublisher.publishEvent(new UserRegisteredEvent(this, user));
        return user;
    }
}

// Listener
@Component
public class EmailNotificationListener {
    @EventListener
    @Async  // xử lý bất đồng bộ – không block main thread
    public void handleUserRegistered(UserRegisteredEvent event) {
        sendWelcomeEmail(event.getUser());
    }
}
```

> **📝 Giải thích chi tiết code:**
> * `UserRegisteredEvent extends ApplicationEvent`: Định nghĩa một lớp sự kiện (Event) mang theo thông tin đối tượng `User` vừa đăng ký thành công. Lớp này cần kế thừa `ApplicationEvent` của Spring.
> * `ApplicationEventPublisher`: Bộ phát sự kiện tích hợp sẵn của Spring Framework.
> * `eventPublisher.publishEvent(...)`: Phát sự kiện ra toàn bộ ứng dụng. Lúc này, `UserService` hoàn thành nhiệm vụ của nó (tạo user) mà hoàn toàn không cần quan tâm xem ai sẽ là người xử lý các bước phụ trợ tiếp theo.
> * `@EventListener`: Đánh dấu phương thức nhận và xử lý sự kiện. Spring sẽ tự phân tích tham số đầu vào (`UserRegisteredEvent`) để tự động định tuyến và gọi phương thức này khi sự kiện tương ứng được phát đi.
> * `@Async`: Chạy xử lý này bất đồng bộ trên một luồng (thread) chạy ngầm riêng biệt của hệ thống. Nhờ đó, việc gửi mail chậm chạp sẽ **không block luồng chạy chính** của user, phản hồi REST API trả về client ngay lập tức mà không phải đợi gửi mail xong.

## 8. Scheduled Tasks

> **🔍 WHAT:** Spring Scheduling cho phép thực thi code theo lịch định kỳ (cron) hoặc theo interval cố định – không cần external scheduler như Quartz cơ bản.
>
> **💡 WHY:** Nhiều tác vụ cần chạy định kỳ mà không phải do user trigger: dọn dẹp dữ liệu cũ, gửi báo cáo hàng ngày, đồng bộ dữ liệu, kiểm tra trạng thái payment đang chờ.
>
> **⚙️ HOW:** Thêm `@EnableScheduling` vào config class. Dùng `@Scheduled` với `cron` (cron expression), `fixedDelay` (sau khi task trước kết thúc), hoặc `fixedRate` (chu kỳ cố định). Nên kết hợp với `@Async` để tránh block scheduler thread.
>
> **📍 WHEN/WHERE:** Cleanup job (hàng đêm 2AM), báo cáo doanh thu hàng ngày/tuần, đồng bộ tỷ giá mỗi giờ, kiểm tra orders timeout sau 30 phút chưa thanh toán.

```java
@Configuration
@EnableScheduling
public class SchedulingConfig {}

@Component
@Slf4j
public class ScheduledTasks {

    // Chạy mỗi ngày lúc 2:00 AM (cron: giây phút giờ ngày tháng thứ)
    @Scheduled(cron = "0 0 2 * * ?")
    public void dailyCleanup() {
        log.info("Running daily cleanup...");
        // xóa data cũ, session hết hạn...
    }

    // Chạy mỗi 30 giây (sau khi task trước kết thúc)
    @Scheduled(fixedDelay = 30000)
    public void checkPendingPayments() {
        log.info("Checking pending payments...");
    }

    // Chạy mỗi 60 giây, delay 5 giây lần đầu
    @Scheduled(initialDelay = 5000, fixedRate = 60000)
    public void syncExchangeRates() {}
}
```

> **📝 Giải thích chi tiết code:**
> * `@EnableScheduling`: Đánh dấu kích hoạt tính năng chạy tác vụ theo lịch trình (Scheduled Tasks) của Spring Boot.
> * `@Scheduled(cron = "0 0 2 * * ?")`: Biểu thức **Cron Expression** định nghĩa lịch chạy. Định dạng của Spring Cron gồm 6 trường: `giây` `phút` `giờ` `ngày_trong_tháng` `tháng` `ngày_trong_tuần`. Ở đây tác vụ được chỉ định chạy chính xác lúc 02:00:00 AM mỗi ngày.
> * `fixedDelay = 30000`: Tác vụ sẽ lặp lại sau mỗi 30 giây (30,000 ms), khoảng thời gian chờ này được tính **sau khi tác vụ trước đó đã chạy xong hoàn toàn**. Rất an toàn khi tác vụ chạy tốn nhiều thời gian không xác định trước.
> * `fixedRate = 60000`: Tác vụ sẽ lặp lại đều đặn mỗi 60 giây, **bất chấp tác vụ trước đó đã kết thúc hay chưa**.
> * `initialDelay = 5000`: Khi ứng dụng Spring Boot vừa khởi chạy thành công, hệ thống sẽ trì hoãn 5 giây trước khi thực thi lần chạy đầu tiên của tác vụ này.

## 9. Actuator (Monitoring)

> **🔍 WHAT:** Spring Boot Actuator cung cấp các HTTP endpoint sẵn có để monitor và quản lý ứng dụng đang chạy: health check, metrics, info, environment, thread dump, v.v.
>
> **💡 WHY:** Production application cần monitoring – biết ứng dụng có đang chạy không, sử dụng bao nhiêu memory/CPU, connection pool còn bao nhiêu. Actuator cung cấp điều này mà không cần code thêm.
>
> **⚙️ HOW:** Thêm `spring-boot-starter-actuator` dependency, cấu hình endpoints cần expose trong yml. Tích hợp với Prometheus để scrape metrics và Grafana để visualize dashboard.
>
> **📍 WHEN/WHERE:** Load balancer dùng `/actuator/health` để kiểm tra trước khi route traffic; Kubernetes liveness/readiness probe; Prometheus scrape `/actuator/prometheus` mỗi 15s; DevOps team check `/actuator/info` để biết version đang chạy.

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-actuator</artifactId>
</dependency>
```

```yaml
management:
  endpoints:
    web:
      exposure:
        include: health,info,metrics,prometheus
  endpoint:
    health:
      show-details: always   # hiển thị chi tiết DB health, disk space...
  info:
    git:
      mode: full             # hiển thị git commit info
```

```bash
GET /actuator/health     → {"status":"UP", "components":{"db":{"status":"UP"},...}}
GET /actuator/info       → version, git info
GET /actuator/metrics    → danh sách metrics
GET /actuator/prometheus → Prometheus format để scrape
```

> **📝 Giải thích chi tiết cấu hình và lệnh:**
> * `include: health,info,metrics,prometheus`: Mặc định Spring Boot ẩn hầu hết các endpoint vì lý do bảo mật. Cấu hình này chỉ định phơi bày (expose) 4 endpoint quan trọng lên giao diện Web HTTP.
> * `show-details: always`: Bật hiển thị chi tiết thông tin sức khỏe hệ thống. Ngoài việc báo ứng dụng hoạt động (`UP`), nó còn kiểm tra chi tiết xem kết nối database còn chạy tốt không, dung lượng ổ đĩa cứng còn đủ không...
> * `/actuator/prometheus`: Cổng dữ liệu cực kỳ quan trọng cho các kỹ sư SRE/DevOps. Định dạng dữ liệu thô sẽ được sinh ra ở định dạng mà hệ thống giám sát **Prometheus** có thể đọc hiểu để vẽ đồ thị hiệu suất lên **Grafana** (như số lượng request/s, lượng RAM tiêu thụ, thời gian xử lý trung bình của API...).
