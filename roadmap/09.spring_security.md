# 09. Spring Security & JWT

> **Mục tiêu:** Bảo mật API với Spring Security, xác thực bằng JWT và phân quyền theo role.

---

## 1. Spring Security – Tổng quan

> **🔍 WHAT:** Spring Security là framework bảo mật toàn diện cho Spring – xử lý authentication (xác thực danh tính) và authorization (phân quyền truy cập) cho ứng dụng web.
>
> **💡 WHY:** Bảo mật là yêu cầu bắt buộc của mọi ứng dụng thực tế. Tự implement bảo mật rất phức tạp và dễ có lỗ hổng. Spring Security cung cấp cơ chế bảo mật battle-tested, handle nhiều attack vector (CSRF, session fixation...).
>
> **⚙️ HOW:** Spring Security sử dụng Filter Chain – mỗi request đi qua chuỗi filter trước khi tới Controller. Filter kiểm tra token, xác thực user, kiểm tra quyền. Nếu không hợp lệ, trả 401/403 trước khi vào Controller.
>
> **📍 WHEN/WHERE:** Bắt buộc cho mọi API có dữ liệu nhạy cảm hoặc cần phân quyền. Cấu hình trong class `SecurityConfig`. Áp dụng cho toàn bộ ứng dụng hoặc cụ thể từng endpoint.

```
Request → SecurityFilterChain
              ↓
   JwtAuthenticationFilter    ← Đọc và validate JWT token
              ↓
    AuthenticationManager      ← Xác thực credentials
              ↓
    UserDetailsService → DB    ← Load user từ DB
              ↓
    SecurityContextHolder      ← Lưu authentication info
              ↓
    Authorization Check        ← Kiểm tra quyền (hasRole...)
              ↓
    Controller / 401 / 403
```

## 2. User Entity & UserDetails

> **🔍 WHAT:** `UserDetails` là interface của Spring Security định nghĩa cách cung cấp thông tin user cho security framework. Entity User phải implement interface này để Spring Security biết cách làm việc với user của bạn.
>
> **💡 WHY:** Spring Security cần biết username, password, authorities (roles) của user theo một chuẩn nhất định. Implement UserDetails kết nối seamlessly Entity của bạn với Spring Security pipeline.
>
> **⚙️ HOW:** Entity User `implements UserDetails`, override các method: `getUsername()` (trả email/username), `getPassword()` (trả hashed password), `getAuthorities()` (trả danh sách roles), và 4 method trạng thái account.
>
> **📍 WHEN/WHERE:** Khai báo trong Entity User class. Kết hợp với `UserDetailsService` interface mà bạn implement để load user từ DB khi authenticate.

```java
@Entity
@Table(name = "users")
@Data @Builder @NoArgsConstructor @AllArgsConstructor
public class User implements UserDetails {

    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(unique = true, nullable = false)
    private String email;

    @Column(nullable = false)
    private String password; // BCrypt hashed

    private String fullName;

    @Enumerated(EnumType.STRING)
    private Role role;

    private boolean active = true;

    // UserDetails methods
    @Override
    public Collection<? extends GrantedAuthority> getAuthorities() {
        return List.of(new SimpleGrantedAuthority("ROLE_" + role.name()));
    }

    @Override public String getUsername() { return email; }
    @Override public boolean isAccountNonExpired() { return true; }
    @Override public boolean isAccountNonLocked() { return true; }
    @Override public boolean isCredentialsNonExpired() { return true; }
    @Override public boolean isEnabled() { return active; }
}
```

> **📝 Giải thích chi tiết code UserDetails:**
> * `implements UserDetails`: Ép buộc lớp `User` (vừa là JPA Entity để map DB) phải triển khai các phương thức của giao diện `UserDetails` để Spring Security có thể trực tiếp lấy dữ liệu bảo mật từ lớp này.
> * `getAuthorities()`: Trả về danh sách quyền hạn (Roles/Authorities) của người dùng. Spring Security quy định tiền tố mặc định cho vai trò là `ROLE_` (ví dụ: `ROLE_USER`, `ROLE_ADMIN`). Ta sử dụng lớp con `SimpleGrantedAuthority` để đóng gói chuỗi vai trò này.
> * `getUsername()`: Trỏ thuộc tính duy nhất đại diện cho tài khoản. Ở đây ứng dụng sử dụng địa chỉ `email` làm username để đăng nhập.
> * `isAccountNonExpired()` / `isAccountNonLocked()` / `isCredentialsNonExpired()`: Các phương thức kiểm tra trạng thái khóa hoặc hết hạn của tài khoản. Ở đây ta trả về mặc định là `true` (không hết hạn, không bị khóa) để đơn giản hóa.
> * `isEnabled()`: Đồng bộ trạng thái hoạt động của tài khoản với thuộc tính `active` trong database. Nếu `active = false`, Spring Security sẽ từ chối không cho phép đăng nhập.

## 3. JWT Service

> **🔍 WHAT:** JWT (JSON Web Token) là chuỗi ký tự mã hóa chứa thông tin user (claims) và chữ ký số để verify. JwtService là class tạo, parse và validate JWT token.
>
> **💡 WHY:** HTTP là stateless – server không nhớ user giữa các request. JWT cho phép stateless authentication – client gửi token mỗi request, server verify chữ ký mà không cần tra cứu DB/session. Phù hợp cho REST API và microservices.
>
> **⚙️ HOW:** JWT gồm 3 phần: Header (algorithm), Payload (claims: userId, role, expiration), Signature (HMAC/RSA). Server ký token bằng secret key khi login, verify chữ ký khi nhận request tiếp theo.
>
> **📍 WHEN/WHERE:** Tạo token trong AuthService khi login/register thành công. Validate token trong JwtAuthenticationFilter cho mỗi request. Access token nên ngắn hạn (15-60 phút), refresh token dài hạn (7-30 ngày).

```java
@Service
public class JwtService {

    @Value("${app.jwt.secret}")
    private String secretKey;

    @Value("${app.jwt.expiration}")
    private long jwtExpiration; // milliseconds

    private SecretKey getSigningKey() {
        return Keys.hmacShaKeyFor(Decoders.BASE64.decode(secretKey));
    }

    // Tạo access token
    public String generateToken(UserDetails userDetails) {
        return Jwts.builder()
            .subject(userDetails.getUsername())
            .issuedAt(new Date())
            .expiration(new Date(System.currentTimeMillis() + jwtExpiration))
            .signWith(getSigningKey())
            .compact();
    }

    // Tạo refresh token (thời gian dài hơn)
    public String generateRefreshToken(UserDetails userDetails) {
        return Jwts.builder()
            .subject(userDetails.getUsername())
            .issuedAt(new Date())
            .expiration(new Date(System.currentTimeMillis() + 7 * 24 * 60 * 60 * 1000L))
            .signWith(getSigningKey())
            .compact();
    }

    public String extractUsername(String token) {
        return Jwts.parser().verifyWith(getSigningKey()).build()
            .parseSignedClaims(token).getPayload().getSubject();
    }

    public boolean isTokenValid(String token, UserDetails userDetails) {
        final String username = extractUsername(token);
        return username.equals(userDetails.getUsername()) && !isTokenExpired(token);
    }

    private boolean isTokenExpired(String token) {
        return Jwts.parser().verifyWith(getSigningKey()).build()
            .parseSignedClaims(token).getPayload().getExpiration().before(new Date());
    }
}
```

> **📝 Giải thích chi tiết code JWT Service (sử dụng thư viện io.jsonwebtoken):**
> * `@Value("${app.jwt.secret}")`: Đọc khóa bí mật (Secret Key) từ file cấu hình `application.yml`. Khóa bí mật này cực kỳ quan trọng, dùng để tạo chữ ký số cho token nhằm ngăn chặn việc sửa đổi thông tin JWT từ phía client.
> * `getSigningKey()`: Giải mã chuỗi secret dạng Base64 và chuyển đổi thành một khóa mật mã an toàn dạng `SecretKey` tương thích với thuật toán HMAC-SHA của thư viện.
> * `Jwts.builder()`: Sử dụng thư viện JJWT để khởi tạo quá trình build token:
>   * `.subject(...)`: Đặt thông tin định danh (ở đây là email của user) vào trường `sub` (Subject) trong Payload của JWT.
>   * `.issuedAt(...)`: Ghi nhận thời điểm phát hành token.
>   * `.expiration(...)`: Thiết lập thời gian hết hạn của token. Quá mốc này, token sẽ không thể sử dụng để truy cập được nữa.
>   * `.signWith(...)`: Thực hiện ký mã hóa kỹ thuật số cho token bằng khóa bí mật.
>   * `.compact()`: Đóng gói toàn bộ cấu trúc và trả về chuỗi JWT dạng mã hóa Base64URL gồm 3 phần phân tách nhau bởi 2 dấu chấm (`Header.Payload.Signature`).
> * `Jwts.parser().verifyWith(...)`: Bộ giải mã token. Nó tự động kiểm tra chữ ký số của token nhận được. Nếu chữ ký không khớp hoặc token đã bị chỉnh sửa, nó sẽ ném ra ngoại lệ `JwtException` ngay lập tức để chặn request.

## 4. JWT Authentication Filter

> **🔍 WHAT:** `JwtAuthenticationFilter` là Servlet Filter chạy trước mỗi request – đọc JWT từ Authorization header, validate và set authentication vào SecurityContext nếu hợp lệ.
>
> **💡 WHY:** Đây là cầu nối giữa JWT token trong request và Spring Security context. Không có filter này, Spring Security không biết request đang được thực hiện bởi ai.
>
> **⚙️ HOW:** Extends `OncePerRequestFilter` (chạy đúng 1 lần/request). Đọc header `Authorization: Bearer <token>`, extract và validate token, load UserDetails từ DB, tạo `UsernamePasswordAuthenticationToken` và set vào `SecurityContextHolder`.
>
> **📍 WHEN/WHERE:** Đăng ký filter này vào SecurityFilterChain với `addFilterBefore(jwtAuthFilter, UsernamePasswordAuthenticationFilter.class)`. Chạy cho EVERY request – filter tự bỏ qua nếu không có token.

```java
@Component
@RequiredArgsConstructor
public class JwtAuthenticationFilter extends OncePerRequestFilter {

    private final JwtService jwtService;
    private final UserDetailsService userDetailsService;

    @Override
    protected void doFilterInternal(
        HttpServletRequest request, HttpServletResponse response, FilterChain filterChain
    ) throws ServletException, IOException {

        final String authHeader = request.getHeader("Authorization");

        // Không có token → tiếp tục (public endpoint sẽ được xử lý tiếp)
        if (authHeader == null || !authHeader.startsWith("Bearer ")) {
            filterChain.doFilter(request, response);
            return;
        }

        final String jwt = authHeader.substring(7);

        try {
            final String userEmail = jwtService.extractUsername(jwt);

            if (userEmail != null && SecurityContextHolder.getContext().getAuthentication() == null) {
                UserDetails userDetails = userDetailsService.loadUserByUsername(userEmail);

                if (jwtService.isTokenValid(jwt, userDetails)) {
                    UsernamePasswordAuthenticationToken authToken =
                        new UsernamePasswordAuthenticationToken(
                            userDetails, null, userDetails.getAuthorities()
                        );
                    authToken.setDetails(new WebAuthenticationDetailsSource().buildDetails(request));
                    SecurityContextHolder.getContext().setAuthentication(authToken);
                }
            }
        } catch (JwtException e) {
            // Token invalid – continue without authentication
        }

        filterChain.doFilter(request, response);
    }
}
```

> **📝 Giải thích chi tiết code JWT Filter:**
> * `extends OncePerRequestFilter`: Kế thừa lớp filter cơ sở để đảm bảo rằng filter này **chỉ thực thi duy nhất 1 lần** cho mỗi HTTP request gửi tới server.
> * `request.getHeader("Authorization")`: Trích xuất Header bảo mật từ HTTP Request. JWT chuẩn luôn được gửi trong header `Authorization` với tiền tố là `Bearer ` (ví dụ: `Bearer eyJhbGci...`).
> * `jwt = authHeader.substring(7)`: Cắt bỏ 7 ký tự đầu tiên (`"Bearer "`) để thu về chuỗi JWT thô nguyên bản.
> * `SecurityContextHolder.getContext().getAuthentication() == null`: Kiểm tra xem người dùng hiện tại của request đã được xác thực (được đưa vào ngữ cảnh bảo mật) trước đó chưa. Nếu chưa (`null`), ta mới tiến hành xác thực.
> * `UsernamePasswordAuthenticationToken`: Đối tượng xác thực tiêu chuẩn của Spring Security. Ta khởi tạo nó bằng việc truyền vào đối tượng `userDetails` (thông tin người dùng), mật khẩu (để `null` vì đã xác thực qua JWT), và danh sách quyền hạn (`userDetails.getAuthorities()`).
> * `SecurityContextHolder.getContext().setAuthentication(authToken)`: **Điểm mấu chốt quan trọng nhất**. Đưa đối tượng xác thực vào Ngữ cảnh bảo mật (Security Context) của Spring. Kể từ dòng lệnh này trở đi, Spring Security ghi nhận request này đã được xác thực thành công và các filter phân quyền phía sau sẽ cho phép request đi qua Controller.

## 5. Security Configuration

> **🔍 WHAT:** `SecurityConfig` là class `@Configuration` định nghĩa `SecurityFilterChain` – quy tắc nào endpoint nào được phép public, nào cần auth, nào cần role cụ thể. Đây là "bộ não" của Spring Security.
>
> **💡 WHY:** Cần một nơi tập trung để khai báo security rules. Mỗi thay đổi quyền truy cập (mở public thêm endpoint, thêm role mới) đều sửa ở đây – dễ audit và review.
>
> **⚙️ HOW:** Build `SecurityFilterChain` với `.authorizeHttpRequests()` để map URL pattern với permission. Disable CSRF (vì dùng JWT stateless). Set `SessionCreationPolicy.STATELESS`. Thêm JwtFilter trước UsernamePasswordAuthenticationFilter.
>
> **📍 WHEN/WHERE:** Một file `SecurityConfig.java` trong package `config/`. Cấu hình một lần, áp dụng cho toàn bộ ứng dụng. Thay đổi cần code review kỹ vì ảnh hưởng bảo mật toàn hệ thống.

```java
@Configuration
@EnableWebSecurity
@EnableMethodSecurity  // bật @PreAuthorize
@RequiredArgsConstructor
public class SecurityConfig {

    private final JwtAuthenticationFilter jwtAuthFilter;

    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
        return http
            .csrf(csrf -> csrf.disable())  // stateless JWT, không cần CSRF
            .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .authorizeHttpRequests(auth -> auth
                // Public endpoints
                .requestMatchers("/api/v1/auth/**").permitAll()
                .requestMatchers("/actuator/health").permitAll()
                .requestMatchers("/swagger-ui/**", "/api-docs/**").permitAll()
                .requestMatchers(HttpMethod.GET, "/api/v1/products/**").permitAll()
                // Admin only
                .requestMatchers("/api/v1/admin/**").hasRole("ADMIN")
                // Tất cả còn lại cần auth
                .anyRequest().authenticated()
            )
            .exceptionHandling(ex -> ex
                .authenticationEntryPoint((req, res, e) -> {
                    res.setContentType("application/json");
                    res.setStatus(401);
                    res.getWriter().write("{\"error\":\"Unauthorized\",\"message\":\"Vui lòng đăng nhập\"}");
                })
                .accessDeniedHandler((req, res, e) -> {
                    res.setContentType("application/json");
                    res.setStatus(403);
                    res.getWriter().write("{\"error\":\"Forbidden\",\"message\":\"Không có quyền truy cập\"}");
                })
            )
            .addFilterBefore(jwtAuthFilter, UsernamePasswordAuthenticationFilter.class)
            .build();
    }

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder(); // hash password mặc định
    }

    @Bean
    public AuthenticationManager authenticationManager(AuthenticationConfiguration config) throws Exception {
        return config.getAuthenticationManager();
    }
}
```

> **📝 Giải thích chi tiết code Security Configuration:**
> * `@EnableWebSecurity`: Bật tính năng tích hợp bảo mật ứng dụng Web của Spring Security.
> * `@EnableMethodSecurity`: Bật hỗ trợ phân quyền ở mức chi tiết trên từng phương thức (Method-level security) bằng cách sử dụng annotation `@PreAuthorize`.
> * `csrf.disable()`: Vô hiệu hóa tính năng chống tấn công giả mạo yêu cầu chéo trang (CSRF - Cross-Site Request Forgery). Vì ứng dụng REST API sử dụng cơ chế JWT **Stateless** (không lưu cookie session ở trình duyệt), nó hoàn toàn miễn nhiễm với kiểu tấn công CSRF.
> * `SessionCreationPolicy.STATELESS`: Ép buộc Spring Security **tuyệt đối không khởi tạo hay lưu trữ Session** trên bộ nhớ server. Server sẽ xử lý mọi request độc lập hoàn toàn, tất cả thông tin định danh bắt buộc phải đính kèm trong token gửi kèm request.
> * `.requestMatchers("/api/v1/auth/**").permitAll()`: Cấu hình cho phép tất cả mọi người (kể cả chưa đăng nhập) được truy cập tự do vào các URL khớp với mẫu đường dẫn này (chuyên dùng cho các API đăng ký/đăng nhập).
> * `.anyRequest().authenticated()`: Ràng buộc an toàn: Tất cả các URL không được cấu hình cụ thể ở phía trên bắt buộc phải đăng nhập thành công mới được truy xuất dữ liệu.
> * `authenticationEntryPoint`: Đăng ký bộ xử lý lỗi tùy biến khi client truy cập vào trang bảo mật mà **chưa đăng nhập (lỗi 401)**. Lệnh này format lỗi về dạng JSON đẹp đẽ thay vì trả về trang trắng lỗi mặc định của Spring.
> * `accessDeniedHandler`: Đăng ký bộ xử lý lỗi khi client **đã đăng nhập nhưng không đủ quyền hạn truy cập (lỗi 403)** (ví dụ: User thường cố tình vào API của Admin).
> * `addFilterBefore(...)`: Đưa filter `jwtAuthFilter` do chúng ta tự viết vào chạy trước filter xác thực tài khoản/mật khẩu mặc định (`UsernamePasswordAuthenticationFilter`) của Spring Security.
> * `BCryptPasswordEncoder`: Cấu hình thuật toán mã hóa mật khẩu một chiều **BCrypt** rất mạnh mẽ. Nó tự động thêm muối (Salt) ngẫu nhiên vào mật khẩu trước khi băm, đảm bảo mật khẩu lưu trong DB tuyệt đối an toàn kể cả khi DB bị lộ.

## 6. Auth Service & Controller

> **🔍 WHAT:** Auth Service chứa logic đăng ký (register) và đăng nhập (login) – validate credentials, tạo user, generate JWT tokens. Auth Controller expose các endpoint `/auth/register` và `/auth/login`.
>
> **💡 WHY:** Tách biệt authentication logic thành service riêng giúp tái sử dụng (có thể gọi từ nhiều chỗ), dễ test và dễ mở rộng (thêm OAuth2, 2FA...).
>
> **⚙️ HOW:** `register`: kiểm tra email tồn tại, hash password bằng BCrypt, save user, generate tokens. `login`: dùng `AuthenticationManager.authenticate()` để validate (tự ném exception nếu sai), generate tokens.
>
> **📍 WHEN/WHERE:** Endpoints public (`/api/v1/auth/**`) không cần JWT. Sau khi login thành công, client lưu access token và gửi trong header `Authorization: Bearer <token>` cho mọi request tiếp theo.

```java
@Service @RequiredArgsConstructor
public class AuthService {
    private final UserRepository userRepository;
    private final PasswordEncoder passwordEncoder;
    private final JwtService jwtService;
    private final AuthenticationManager authManager;

    public AuthResponse register(RegisterRequest request) {
        if (userRepository.existsByEmail(request.getEmail())) {
            throw new EmailAlreadyExistsException("Email đã được sử dụng");
        }
        User user = User.builder()
            .email(request.getEmail())
            .password(passwordEncoder.encode(request.getPassword()))
            .fullName(request.getFullName())
            .role(Role.USER).build();
        user = userRepository.save(user);

        return AuthResponse.builder()
            .accessToken(jwtService.generateToken(user))
            .refreshToken(jwtService.generateRefreshToken(user))
            .build();
    }

    public AuthResponse login(LoginRequest request) {
        authManager.authenticate(  // ném BadCredentialsException nếu sai
            new UsernamePasswordAuthenticationToken(request.getEmail(), request.getPassword())
        );
        User user = userRepository.findByEmail(request.getEmail()).orElseThrow();
        return AuthResponse.builder()
            .accessToken(jwtService.generateToken(user))
            .refreshToken(jwtService.generateRefreshToken(user))
            .build();
    }
}

@RestController
@RequestMapping("/api/v1/auth")
@RequiredArgsConstructor
public class AuthController {
    private final AuthService authService;

    @PostMapping("/register")
    public ResponseEntity<AuthResponse> register(@RequestBody @Valid RegisterRequest request) {
        return ResponseEntity.status(201).body(authService.register(request));
    }

    @PostMapping("/login")
    public ResponseEntity<AuthResponse> login(@RequestBody @Valid LoginRequest request) {
        return ResponseEntity.ok(authService.login(request));
    }
}
```

> **📝 Giải thích chi tiết code Nghiệp vụ Auth:**
> * `passwordEncoder.encode(...)`: Mã hóa mật khẩu một chiều của người dùng bằng thuật toán BCrypt đã cấu hình trước khi lưu xuống database. Tuyệt đối không lưu mật khẩu dạng bản rõ (Plaintext) vào DB!
> * `authManager.authenticate(...)`: Ủy thác nhiệm vụ kiểm tra thông tin đăng nhập cho `AuthenticationManager` của Spring. Nó sẽ tự động gọi phương thức load user từ DB lên để so sánh mật khẩu. Nếu sai mật khẩu hoặc tài khoản không tồn tại, nó sẽ **tự động ném ra ngoại lệ `BadCredentialsException`**. Khi đó, phương thức của chúng ta lập tức bị dừng lại và bộ Global Exception Handler sẽ tự động format lỗi trả về cho client.
> * `AuthResponse`: Chứa thông tin cặp Token gồm: `accessToken` (để gọi API thời hạn ngắn) và `refreshToken` (để client dùng tự động đổi access token mới khi hết hạn mà không cần bắt người dùng đăng nhập lại từ đầu).

## 7. Method-Level Security

> **🔍 WHAT:** Method-level security cho phép khai báo authorization rule trực tiếp trên method bằng annotation `@PreAuthorize`, `@PostAuthorize` thay vì chỉ cấu hình URL pattern trong SecurityConfig.
>
> **💡 WHY:** URL-based security không đủ tinh tế – ví dụ "user chỉ được xem order của chính mình, admin xem được tất cả" không thể express chỉ bằng URL pattern. Method security cho phép điều kiện phức tạp hơn với SpEL.
>
> **⚙️ HOW:** Bật với `@EnableMethodSecurity`. Dùng `@PreAuthorize("hasRole('ADMIN')")` hoặc `@PreAuthorize("#id == authentication.principal.id")` để kiểm tra theo tham số. `authentication.principal` là UserDetails object hiện tại.
>
> **📍 WHEN/WHERE:** Dùng khi security rule phụ thuộc vào dữ liệu (resource owner check), không phải chỉ role. Đặt ở Service layer để bảo vệ logic dù được gọi từ Controller hay event listener.

```java
@Service
public class UserService {

    @PreAuthorize("hasRole('ADMIN')")
    public List<User> getAllUsers() { /* chỉ Admin */ }

    // User xem info của chính mình, Admin xem được tất cả
    @PreAuthorize("hasRole('ADMIN') or #id == authentication.principal.id")
    public UserResponse getUserById(Long id) { /* ... */ }

    @PreAuthorize("hasAnyRole('ADMIN', 'MODERATOR')")
    public void banUser(Long userId) { /* ... */ }
}

// Lấy user đang đăng nhập hiện tại
@GetMapping("/me")
public ResponseEntity<UserResponse> getCurrentUser(
    @AuthenticationPrincipal User currentUser  // inject từ SecurityContext
) {
    return ResponseEntity.ok(toResponse(currentUser));
}
```

> **📝 Giải thích chi tiết code Phân quyền mức Phương thức:**
> * `@PreAuthorize`: Khai báo điều kiện bảo mật trước khi thực thi hàm bằng ngôn ngữ diễn đạt **SpEL (Spring Expression Language)**. Nếu điều kiện không thỏa mãn, Spring sẽ ném ra ngoại lệ `AccessDeniedException` (trả về lỗi 403) ngay lập tức.
> * `#id == authentication.principal.id`: So sánh tham số `id` truyền vào hàm với thuộc tính `id` bóc tách từ đối tượng người dùng đang đăng nhập hiện tại lưu trong context (`authentication.principal`), đảm bảo người dùng bình thường tuyệt đối không thể hack xem trộm dữ liệu cá nhân của người dùng khác.
> * `@AuthenticationPrincipal`: Annotation cực kỳ tiện lợi của Spring Boot. Nó tự động truy cập vào Security Context hiện tại để bóc tách và tiêm (inject) thẳng đối tượng `User` đang đăng nhập vào tham số `currentUser` của API, giúp ta lấy thông tin người dùng hiện tại siêu nhanh mà không cần viết các câu lệnh truy vấn thủ công.
