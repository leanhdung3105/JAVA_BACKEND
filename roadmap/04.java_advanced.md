## 1. Generics

> **🔍 WHAT:** Generics cho phép viết code với kiểu dữ liệu tham số hóa (type parameter) – một class/method có thể hoạt động với nhiều kiểu dữ liệu khác nhau mà vẫn đảm bảo type-safety.
>
> **💡 WHY:** Trước Generics phải dùng `Object` và cast thủ công – dễ gây `ClassCastException` khi chạy. Generics phát hiện lỗi kiểu dữ liệu ngay lúc compile, code rõ ràng và an toàn hơn.
>
> **⚙️ HOW:** Khai báo type parameter trong `<>`. Bounded wildcards: `<T extends Number>` giới hạn T phải là subtype của Number. `<? extends X>` đọc (producer), `<? super X>` ghi (consumer).
>
> **📍 WHEN/WHERE:** Spring Data Repository dùng `JpaRepository<Entity, ID>`; ApiResponse wrapper `ApiResponse<T>`; mọi Collection đều dùng Generics. Bất kỳ class "container" nào cần type-safe.

```java
// Generic class
public class Box<T> {
    private T value;
    public Box(T value) { this.value = value; }
    public T getValue() { return value; }
}

Box<String> strBox = new Box<>("Hello");
Box<Integer> intBox = new Box<>(42);

// Generic method
public static <T extends Comparable<T>> T findMax(List<T> list) {
    T max = list.get(0);
    for (T item : list) {
        if (item.compareTo(max) > 0) max = item;
    }
    return max;
}

// Bounded wildcards
public static double sumList(List<? extends Number> list) {
    return list.stream().mapToDouble(Number::doubleValue).sum();
}

sumList(List.of(1, 2, 3));        // List<Integer>
sumList(List.of(1.5, 2.5, 3.0)); // List<Double>
```

> **📝 Giải thích chi tiết code:**
> * `public class Box<T>`: Khai báo một lớp Generic. Ký tự `<T>` đại diện cho một kiểu dữ liệu tham số hóa (Type Parameter) sẽ được xác định cụ thể khi ta khởi tạo đối tượng (ví dụ: `new Box<String>("Hello")`).
> * `<T extends Comparable<T>> T findMax(...)`: 
>   * `<T extends Comparable<T>>`: Khai báo ràng buộc kiểu (Bounded Type Parameter). Ép buộc kiểu `T` truyền vào phương thức này phải kế thừa hoặc implement interface `Comparable<T>` để đảm bảo đối tượng đó có khả năng so sánh qua phương thức `compareTo`.
>   * `T` đứng trước tên phương thức xác định kiểu dữ liệu trả về của phương thức đó chính là kiểu `T`.
> * `List<? extends Number>`: Sử dụng **Bounded Wildcard** dạng Upper Bound (`? extends`). Nó chấp nhận bất kỳ kiểu dữ liệu nào miễn là lớp con của lớp `Number` (như `Integer`, `Double`, `Float`...). Trong phương thức `sumList`, ta chỉ thực hiện đọc dữ liệu ra (Producer - PECS rule: Producer Extends, Consumer Super) để tính tổng.

## 2. Functional Interfaces & Lambda

> **🔍 WHAT:** Functional Interface là interface có đúng 1 abstract method. Lambda là cú pháp ngắn gọn để tạo instance của Functional Interface – viết function như một giá trị.
>
> **💡 WHY:** Lập trình hàm (functional style) giúp code ngắn gọn, không cần tạo anonymous class. Là nền tảng của Stream API và reactive programming. Method reference càng rút ngắn code hơn nữa.
>
> **⚙️ HOW:** Lambda: `(params) -> expression`. Java cung cấp sẵn: `Predicate<T>` (kiểm tra điều kiện), `Function<T,R>` (biến đổi), `Consumer<T>` (tiêu thụ), `Supplier<T>` (tạo ra). Method reference: `ClassName::methodName`.
>
> **📍 WHEN/WHERE:** Stream API (filter, map, forEach), Spring Event listeners, CompletableFuture callbacks, Spring Security authorization rules, custom Comparator sorting.

```java
import java.util.function.*;

// Predicate – kiểm tra điều kiện
Predicate<String> isLong = s -> s.length() > 5;
isLong.test("Hello");   // false
isLong.test("Hi Java"); // true

// Function – biến đổi
Function<String, Integer> strLen = String::length; // method reference
strLen.apply("Hello"); // 5

// Consumer – thực hiện tác vụ
Consumer<String> printer = System.out::println;
printer.accept("Hello!");

// Supplier – tạo giá trị
Supplier<String> greeting = () -> "Hello, World!";
greeting.get();

// BiFunction
BiFunction<String, Integer, String> repeat = (s, n) -> s.repeat(n);
repeat.apply("abc", 3); // "abcabcabc"

// UnaryOperator
UnaryOperator<String> toUpper = String::toUpperCase;
toUpper.apply("hello"); // "HELLO"
```

> **📝 Giải thích chi tiết code:**
> * `Predicate<String>`: Nhận vào một đối tượng kiểu `String` và trả về kết quả kiểu `boolean` thông qua phương thức `test(T t)`. Lambda `s -> s.length() > 5` định nghĩa logic kiểm tra xem độ dài chuỗi có lớn hơn 5 hay không.
> * `String::length`: Đây là cú pháp **Method Reference** (Tham chiếu phương thức). Nó là cách viết ngắn gọn hơn nữa của biểu thức Lambda `s -> s.length()`. Java tự động hiểu phương thức `length()` của class `String` sẽ được gọi trên đối tượng String đầu vào.
> * `Consumer<String>`: Nhận vào tham số và tiêu thụ (xử lý) nó qua phương thức `accept(T t)` nhưng **không trả về giá trị** (void). Ở đây tham chiếu tới phương thức in dữ liệu: `System.out::println`.
> * `Supplier<String>`: Phương thức `get()` **không nhận tham số đầu vào nhưng trả về một đối tượng** kiểu `String`. Nó thường dùng để trì hoãn việc sinh ra giá trị (Lazy evaluation) cho tới khi thật sự cần dùng đến.
> * `BiFunction<String, Integer, String>`: Nhận vào hai tham số kiểu `String` và `Integer`, trả về một kết quả kiểu `String` thông qua phương thức `apply(T t, U u)`.
> * `UnaryOperator<String>`: Là một dạng đặc biệt của `Function`, nơi cả kiểu dữ liệu đầu vào và đầu ra đều giống nhau (đều là `String`).

## 3. Stream API

> **🔍 WHAT:** Stream API cung cấp cách xử lý tập hợp dữ liệu theo phong cách functional – pipeline các thao tác lọc, biến đổi, tổng hợp trên Collection mà không cần vòng lặp thủ công.
>
> **💡 WHY:** Code với Stream ngắn hơn, rõ ý định hơn và dễ song song hóa (parallelStream) so với vòng lặp for truyền thống. Là cách xử lý dữ liệu phổ biến nhất trong Java hiện đại.
>
> **⚙️ HOW:** Bắt đầu bằng `collection.stream()`, nối các **intermediate operations** (filter, map, sorted – lazy), kết thúc bằng **terminal operation** (collect, count, forEach, reduce – eager). Stream chỉ dùng 1 lần.
>
> **📍 WHEN/WHERE:** Xử lý danh sách trong Service layer – lọc users theo điều kiện, transform Entity sang DTO, nhóm data theo category, tính tổng/trung bình. Không nên dùng trong JPA query (dùng JPQL/SQL thay thế).

```java
List<String> names = List.of("Alice", "Bob", "Charlie", "David", "Ann");

// filter – lọc
List<String> longNames = names.stream()
    .filter(n -> n.length() > 3)
    .collect(Collectors.toList()); // ["Alice", "Charlie", "David"]

// map – biến đổi
List<Integer> lengths = names.stream()
    .map(String::length)
    .collect(Collectors.toList()); // [5, 3, 7, 5, 3]

// sorted, distinct
List<Integer> sorted = List.of(3, 1, 4, 1, 5, 9, 2, 6).stream()
    .distinct().sorted().collect(Collectors.toList()); // [1, 2, 3, 4, 5, 6, 9]

// reduce – gộp lại
int sum = List.of(1, 2, 3, 4, 5).stream()
    .reduce(0, Integer::sum); // 15

// collect vào Map
Map<Integer, List<String>> byLength = names.stream()
    .collect(Collectors.groupingBy(String::length));

// flatMap – làm phẳng nested list
List<List<Integer>> nested = List.of(List.of(1, 2), List.of(3, 4));
List<Integer> flat = nested.stream()
    .flatMap(Collection::stream)
    .collect(Collectors.toList()); // [1, 2, 3, 4]

// Numeric streams
IntStream.rangeClosed(1, 5).sum();     // 15
IntStream.rangeClosed(1, 5).average(); // OptionalDouble[3.0]
```

> **📝 Giải thích chi tiết code:**
> * `names.stream()`: Chuyển đổi Collection thành luồng tuần tự (Stream). Lúc này dữ liệu chưa được xử lý, Stream hoạt động theo cơ chế **Lazy Evaluation** (chỉ chạy khi có thao tác kết thúc).
> * `filter(n -> n.length() > 3)`: Một **Intermediate Operation** (thao tác trung gian). Nó nhận vào một `Predicate` để lọc ra các phần tử thỏa mãn điều kiện. Kết quả của thao tác trung gian vẫn là một Stream.
> * `collect(Collectors.toList())`: Một **Terminal Operation** (thao tác kết thúc). Nó thu gom dữ liệu từ Stream và đóng gói ngược lại vào một `List` cụ thể. Sau khi chạy thao tác này, Stream sẽ tự động đóng lại và không thể tái sử dụng.
> * `map(String::length)`: Thao tác trung gian để chuyển đổi kiểu dữ liệu của từng phần tử trong Stream (từ String sang độ dài của chuỗi là Integer).
> * `distinct().sorted()`: Loại bỏ các phần tử trùng lặp (`distinct`) và sắp xếp mảng theo thứ tự tăng dần (`sorted`).
> * `reduce(0, Integer::sum)`: Thao tác gộp tất cả phần tử trong Stream thành một kết quả duy nhất. Số `0` là giá trị khởi tạo (Identity). Hàm `Integer::sum` sẽ cộng dồn từng phần tử vào biến tích lũy.
> * `Collectors.groupingBy(...)`: Nhóm các phần tử trong Stream thành một `Map`, với Key là độ dài chuỗi, và Value là List các chuỗi có độ dài tương ứng.
> * `flatMap(Collection::stream)`: Thao tác trung gian đặc biệt dùng để xử lý các Stream chứa các Collection lồng nhau. Nó "làm phẳng" cấu trúc đa tầng thành một Stream một chiều duy nhất chứa toàn bộ các phần tử thô.
> * `IntStream.rangeClosed(1, 5)`: Tạo ra một Stream kiểu số nguyên nguyên thủy (`int`) chạy từ `1` đến `5` (bao gồm cả 5), tránh việc boxing lên class `Integer` giúp tăng tối đa hiệu suất tính toán số học.

## 4. Optional

> **🔍 WHAT:** `Optional<T>` là container có thể chứa hoặc không chứa giá trị, là cách Java xử lý "giá trị có thể null" một cách an toàn và rõ ràng.
>
> **💡 WHY:** `NullPointerException` là lỗi phổ biến nhất trong Java. Optional buộc lập trình viên phải xử lý trường hợp không có giá trị, thay vì bị NPE bất ngờ khi runtime.
>
> **⚙️ HOW:** `Optional.of(value)` (không null), `Optional.ofNullable(value)` (có thể null), `Optional.empty()`. Dùng `map()`, `filter()`, `orElse()`, `orElseThrow()`, `ifPresent()` để xử lý an toàn.
>
> **📍 WHEN/WHERE:** Repository `findById()` trả `Optional<Entity>`; Service layer dùng `orElseThrow()` để ném exception khi không tìm thấy. Không nên dùng Optional làm field của class hay tham số method.

```java
// Tạo Optional
Optional<String> opt = Optional.of("Hello");
Optional<String> empty = Optional.empty();
Optional<String> nullable = Optional.ofNullable(null); // empty

opt.isPresent();          // true
opt.get();                // "Hello"
opt.orElse("default");    // "Hello"
empty.orElse("default");  // "default"
empty.orElseGet(() -> computeDefault()); // lazy
opt.orElseThrow(() -> new RuntimeException("Not found"));

// map & filter
Optional<Integer> length = Optional.of("Hello").map(String::length); // Optional[5]

// ifPresent
opt.ifPresent(s -> System.out.println("Giá trị: " + s));

// Chuỗi Optional (tránh NPE khi truy cập nested object)
String city = Optional.ofNullable(user)
    .map(User::getAddress)
    .map(Address::getCity)
    .orElse("Unknown");
```

> **📝 Giải thích chi tiết code:**
> * `Optional.of(value)` vs `Optional.ofNullable(value)`:
>   * `of(...)`: Tạo Optional chứa giá trị. Nếu giá trị truyền vào là `null`, nó sẽ lập tức ném ra lỗi `NullPointerException`.
>   * `ofNullable(...)`: Chấp nhận cả giá trị `null`. Nếu là `null`, nó sẽ trả về một `Optional.empty()` an toàn.
> * `orElse("default")`: Lấy giá trị bên trong Optional. Nếu Optional rỗng (`empty`), trả về chuỗi mặc định là `"default"`.
> * `orElseGet(() -> computeDefault())`: Tương tự như `orElse`, nhưng nhận vào một `Supplier`. Lợi ích lớn là hàm `computeDefault()` sẽ **chỉ được gọi và tính toán khi Optional thực sự rỗng**, tối ưu hiệu suất hơn `orElse` vốn luôn tính toán giá trị mặc định ngay khi truyền tham số.
> * `orElseThrow(...)`: Nếu Optional rỗng, tự động ném ra ngoại lệ được định nghĩa sẵn. Đây là mô-típ viết code cực kỳ phổ biến trong Spring Boot Service layer (ví dụ: `userRepository.findById(id).orElseThrow(() -> new UserNotFoundException(id))`).
> * `ifPresent(s -> ...)`: Chỉ thực thi khối lệnh Lambda bên trong nếu Optional thực sự chứa giá trị, giúp loại bỏ các câu lệnh `if (x != null)` rườm rà.
> * `Chuỗi Optional`: Kỹ thuật chaining cực kỳ tinh tế giúp tránh lỗi NPE. Nếu bất kỳ mắt xích nào (`user`, `address`, hay `city`) bị `null`, toàn bộ chuỗi xử lý sẽ dừng lại an toàn và trả về giá trị mặc định là `"Unknown"`.

## 5. Concurrency & Multithreading

> **🔍 WHAT:** Concurrency là khả năng thực thi nhiều task đồng thời (hoặc xen kẽ). Multithreading là cơ chế chạy nhiều luồng trong cùng một process, chia sẻ bộ nhớ.
>
> **💡 WHY:** Server phải xử lý hàng trăm/nghìn request đồng thời. Spring Boot tự xử lý multithreading cho HTTP requests, nhưng cần hiểu để xử lý background jobs, async tasks, và tránh race condition.
>
> **⚙️ HOW:** Dùng `ExecutorService` (quản lý thread pool) thay vì tạo Thread thủ công. `CompletableFuture` cho async programming. `synchronized`, `Lock`, `AtomicInteger` để xử lý thread-safety khi share state.
>
> **📍 WHEN/WHERE:** Gửi email sau khi đăng ký (`@Async`); gọi nhiều external API song song (`CompletableFuture.allOf`); scheduled jobs (`@Scheduled`); batch processing. Trong Spring Boot thường dùng `@Async` hơn là raw Thread.

```java
// ExecutorService – quản lý thread pool
ExecutorService executor = Executors.newFixedThreadPool(4);
executor.submit(() -> System.out.println("Task 1"));
executor.submit(() -> System.out.println("Task 2"));
executor.shutdown();

// CompletableFuture – async programming
CompletableFuture<String> future = CompletableFuture.supplyAsync(() -> {
    // long operation in background thread
    return "Result";
});

// Chain async operations
CompletableFuture.supplyAsync(() -> fetchUserFromDB(userId))
    .thenApply(user -> enrichWithData(user))
    .thenAccept(user -> sendNotification(user))
    .exceptionally(ex -> {
        System.err.println("Lỗi: " + ex.getMessage());
        return null;
    });

// Kết hợp nhiều future
CompletableFuture<String> f1 = CompletableFuture.supplyAsync(() -> "Hello");
CompletableFuture<String> f2 = CompletableFuture.supplyAsync(() -> "World");
f1.thenCombine(f2, (a, b) -> a + " " + b).get(); // "Hello World"

// Thread-safe counter
AtomicInteger counter = new AtomicInteger(0);
counter.incrementAndGet();
```

> **📝 Giải thích chi tiết code:**
> * `Executors.newFixedThreadPool(4)`: Khởi tạo một **Thread Pool** chứa cố định 4 luồng chạy hoạt động ngầm. Việc tái sử dụng thread giúp hệ thống tránh khỏi chi phí nặng nề của việc liên tục tạo mới và hủy bỏ thread vật lý của hệ điều hành. Lệnh `shutdown()` báo hiệu cho pool dừng nhận nhiệm vụ mới và sẽ giải phóng tài nguyên sau khi các nhiệm vụ hiện tại chạy xong.
> * `CompletableFuture.supplyAsync(...)`: Khởi chạy một tiến trình bất đồng bộ (Asynchronous task) dưới background thread, không block luồng chạy chính của chương trình. Kết quả trả về sau đó sẽ được đóng gói vào đối tượng `CompletableFuture`.
> * `thenApply` / `thenAccept` / `exceptionally`: Chuỗi các callback bất đồng bộ tinh tế:
>   * `thenApply`: Nhận kết quả từ bước trước, biến đổi dữ liệu (Function) và truyền tiếp.
>   * `thenAccept`: Nhận kết quả cuối cùng, thực thi hành động tiêu thụ (Consumer) không trả kết quả.
>   * `exceptionally`: Trình bắt lỗi tập trung (giống try-catch) dành riêng cho toàn bộ chuỗi bất đồng bộ phía trên.
> * `f1.thenCombine(...)`: Chạy song song hai tiến trình độc lập `f1` và `f2`. Khi cả hai đều hoàn thành, nó sẽ gộp kết quả của cả hai lại để xử lý tiếp. Lệnh `.get()` được dùng để block luồng chính và đợi lấy kết quả cuối cùng.
> * `AtomicInteger counter`: Đối tượng đếm số nguyên an toàn trong môi trường đa luồng (Thread-safe). Nó sử dụng cơ chế phần cứng **CAS (Compare-And-Swap)** để đảm bảo phương thức `incrementAndGet()` thực thi nguyên tử (atomic) mà không cần dùng đến từ khóa `synchronized` gây chậm hiệu suất.

## 6. Java I/O & NIO

> **🔍 WHAT:** Java I/O (java.io) là API đọc/ghi file theo luồng (stream-based). NIO (java.nio, Java 7+) cung cấp API hiện đại hơn với `Path`, `Files`, non-blocking I/O.
>
> **💡 WHY:** Đọc/ghi file là nhu cầu phổ biến: đọc config file, xử lý file upload, ghi log, export CSV/Excel. NIO đơn giản hơn và hiệu quả hơn I/O cũ cho hầu hết use case.
>
> **⚙️ HOW:** Dùng `Files` class với `Path` object: `Files.readString()`, `Files.writeString()`, `Files.lines()` (stream cho file lớn). Luôn dùng `try-with-resources` để tự đóng stream.
>
> **📍 WHEN/WHERE:** Đọc config/template file trong resources; xử lý file upload (MultipartFile trong Spring); export báo cáo; import dữ liệu từ CSV. Trong Spring Boot thường dùng `Resource` và `ResourceLoader` thay vì raw I/O.

```java
import java.nio.file.*;

// Đọc file (file nhỏ)
String content = Files.readString(Path.of("file.txt"));
List<String> lines = Files.readAllLines(Path.of("file.txt"));

// Ghi file
Files.writeString(Path.of("output.txt"), "Hello World\n");

// Stream file lớn – lazy, tránh load hết vào memory
try (Stream<String> stream = Files.lines(Path.of("largefile.txt"))) {
    stream.filter(line -> line.contains("ERROR"))
          .forEach(System.out::println);
}

// Thao tác file system
Files.exists(Path.of("file.txt"));
Files.createDirectory(Path.of("mydir"));
Files.delete(Path.of("file.txt"));
```

> **📝 Giải thích chi tiết code:**
> * `Path.of("file.txt")`: Lớp định vị đường dẫn file trong hệ thống, thay thế cho lớp `File` truyền thống.
> * `Files.readString(...)`: Tiện ích cực kỳ nhanh của NIO để đọc toàn bộ nội dung của một file văn bản nhỏ vào trong một biến String duy nhất chỉ bằng 1 dòng lệnh.
> * `Files.lines(...)`: Giải pháp đọc các file dung lượng cực lớn (lên tới hàng Gigabyte). Nó không nạp toàn bộ file vào RAM mà trả về một `Stream<String>` đọc file theo kiểu **Lazy/Stream** (đọc đến đâu nạp đến đó). Phải bao bọc trong `try-with-resources` để giải phóng handle file của hệ điều hành ngay khi xử lý xong.

## 7. Java 17+ Features quan trọng

> **🔍 WHAT:** Java 17+ giới thiệu nhiều tính năng mới: Sealed Classes (giới hạn subclass), Pattern Matching (switch nâng cao), Text Blocks, Records – giúp code ngắn gọn và type-safe hơn.
>
> **💡 WHY:** Các tính năng mới giải quyết code lặp (Records thay POJO), tăng type-safety (Sealed classes), và viết code biểu cảm hơn (switch pattern matching). Spring Boot 3.x yêu cầu Java 17+.
>
> **⚙️ HOW:** Sealed classes dùng `sealed` + `permits` để liệt kê các subclass được phép. Pattern matching trong switch tự động cast và kiểm tra kiểu. Text block dùng `"""` cho multi-line string.
>
> **📍 WHEN/WHERE:** Sealed classes cho domain model của DDD; Pattern matching khi xử lý nhiều loại event/command; Text blocks cho SQL query và JSON template; Records cho DTO (đã đề cập ở OOP).

```java
// Sealed classes – giới hạn subclass
public sealed interface Shape permits Circle, Rectangle, Triangle {}
public record Circle(double radius) implements Shape {}
public record Rectangle(double width, double height) implements Shape {}

// Pattern Matching với switch (Java 21)
String describe(Object obj) {
    return switch (obj) {
        case Integer i -> "int: " + i;
        case String s when s.isEmpty() -> "empty string";
        case String s -> "string: " + s;
        case null -> "null";
        default -> "other: " + obj;
    };
}

// Tính diện tích với sealed + switch – exhaustive, compiler check
double area(Shape shape) {
    return switch (shape) {
        case Circle c -> Math.PI * c.radius() * c.radius();
        case Rectangle r -> r.width() * r.height();
        case Triangle t -> /* ... */;
        // Không cần default vì sealed class bao hết
    };
}

// Text Blocks (Java 15+) – SQL, JSON dễ đọc hơn
String sql = """
        SELECT u.name, u.email
        FROM users u
        WHERE u.active = true
        ORDER BY u.name
        """;
```

> **📝 Giải thích chi tiết code:**
> * `public sealed interface Shape permits ...`: Khai báo một **Sealed Interface** (Giao diện bị đóng). Nó chỉ định rõ ràng duy nhất 3 class con là `Circle`, `Rectangle`, và `Triangle` được phép triển khai interface này. Bất kỳ lớp nào khác cố tình implement `Shape` sẽ bị trình biên dịch chặn lại ngay lập tức.
> * `case Integer i -> ...`: Khái niệm **Pattern Matching trong Switch** (áp dụng từ Java 21). Nó tự động kiểm tra xem đối tượng có phải kiểu `Integer` hay không, nếu đúng, nó tự động ép kiểu (cast) đối tượng đó thành biến `i` để ta sử dụng luôn trong biểu thức phía sau.
> * `case String s when s.isEmpty()`: Kết hợp lọc điều kiện bổ sung (`when s.isEmpty()`) trực tiếp trong cấu trúc switch-case rất ngắn gọn và trực quan.
> * `exhaustive compiler check`: Điểm cực mạnh khi kết hợp **Sealed Class** và **Switch Expression**. Vì trình biên dịch đã biết chắc chắn interface `Shape` chỉ có đúng 3 lớp con, nên ta không cần viết nhánh `default`. Nếu sau này bạn thêm lớp con thứ tư vào danh sách `permits` mà quên cập nhật trong switch-case tính diện tích, trình biên dịch sẽ báo lỗi đỏ ngay lúc build để nhắc nhở bạn.
